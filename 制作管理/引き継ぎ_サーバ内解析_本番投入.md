## 3. 作業手順

### 前提: 実行環境の確認

作業前に、そこが本当に本番機かを確認する。

```bash
ls /etc/apache2/sites-enabled/          # bits-keep-ssl.conf があること
pg_isready                              # PostgreSQL が応答すること
cat bits-keep/.env | grep DB_           # DB_CONNECTION=pgsql であること
```

`.env` が `sqlite` になっていたら**そのまま作業を進めてはならない**。本番DBが空のSQLiteへ切り替わる事故になる。

### 手順1: PDF 変換ツールを入れる

```bash
sudo apt install poppler-utils
pdftotext -v && pdftoppm -v
```

パスが `/usr/bin/` 以外なら `.env` に `PDFTOTEXT_BINARY` / `PDFTOPPM_BINARY` を設定する。

### 手順2: Codex CLI を入れる

```bash
sudo npm install -g @openai/codex
codex --version
```

パスが `/usr/local/bin/codex` 以外なら `.env` に `CODEX_BINARY` を設定する。

### 手順3: 解析専用ディレクトリを作る

```bash
sudo mkdir -p /var/lib/bitskeep-codex
sudo chown www-data:www-data /var/lib/bitskeep-codex
sudo chmod 700 /var/lib/bitskeep-codex
```

**認証トークンは自動更新されるため、書き込み可能でなければならない。** 読み取り専用にすると、しばらく動いたあと突然失効する。
Web サーバ実行ユーザのホーム（`/var/www` など）を流用しないこと。

### 手順4: サーバ上でログインする

本番サーバにブラウザがないため、デバイスコード方式を使う。表示されたコードを手元のブラウザで承認する。

```bash
sudo -u www-data CODEX_HOME=/var/lib/bitskeep-codex HOME=/var/lib/bitskeep-codex \
  codex login --device-auth
```

確認: `/var/lib/bitskeep-codex/auth.json` が生成されること。

### 手順5: キューワーカーを常駐させる

**この手順を飛ばすと機能が一切動かない。** 解析は `順番待ち` のまま永久に進まない。

systemd 等で以下を常駐させる。

```bash
php artisan queue:work --queue=default --tries=1
```

- サーバ再起動後も自動復帰すること
- `CODEX_HOME=/var/lib/bitskeep-codex` を worker の環境に渡すこと（`.env` に書けば足りる）
- **`composer run dev` と `php artisan serve` は絶対に実行しない**（`public/hot` が生成され CSS/JS が全滅する。詳細は `CLAUDE.md`）

### 手順6: 本番DBへ migration を適用する

対象は `datasheet_analyses` の**新規追加のみ**。既存テーブルへの破壊的変更はない。

**実行前に、以下4点を `制作管理/makinglog.md` へ記録すること。記録なしの実行は禁止。**

1. 接続先確認（`.env` の `DB_CONNECTION` / `DB_HOST` / `DB_DATABASE` の実値）
2. 件数確認（主要テーブルのレコード件数）
3. バックアップ確認（取得済みバックアップの所在と取得日時）
4. 復元手段確認（そのバックアップから戻す具体的手順）

記録後に実行:

```bash
php artisan migrate --force
```

**禁止**: `db:wipe` `migrate:fresh` `truncate` `drop` は実行しない。

### 手順7: 連携設定で状態を確認する

ブラウザで `https://bits-keep.rwc.0t0.jp/settings/integrations` を開き、
`解析の実行方式` セクションで `サーバ内解析` が **`利用可能`** になっていることを確認する。

`要設定` のままなら、そこに不足内容がそのまま表示されている。手順1〜4のどれかが未完了。

### 手順8: 実データシートで実測する

**`codex exec` を実際に走らせた実績は引き継ぎ時点で0件である。** ここが最大の未検証領域。

対象: テキスト層ありのPDFとスキャンPDFの**両方**を含む3〜5件。

記録する項目:

- 解析1件あたりの所要時間
- `input_mode`（`text` / `image` のどちらで処理されたか。`datasheet_analyses` テーブルに記録される）
- 抽出したスペック件数と、明らかな誤り
- 利用枠の消費量

調整の目安:

| 症状 | 見直す設定 |
|---|---|
| 時間超過が頻発 | `DATASHEET_ANALYSIS_TIMEOUT`（既定300秒） |
| スキャンPDFの精度不足 | `DATASHEET_PDF_IMAGE_DPI`（既定150） |
| テキストPDFなのに画像化される | `DATASHEET_PDF_TEXT_THRESHOLD`（既定800文字） |
| 利用枠の消費が多すぎる | `DATASHEET_PDF_MAX_IMAGE_PAGES`（既定12ページ） |

### 手順9: 実機E2E確認

部品登録画面から通しで確認する。

1. `/components/create` を開き、データシートPDFを選択
2. `データシートから自動入力` を押す
3. 進行表示が `順番待ち` → `変換中` → `解析中` と進むこと
4. **解析中にブラウザを再読込し、進行中の解析へ復帰すること**（本件の主目的の一つ）
5. **解析中に別画面へ移動して戻り、続きが表示されること**
6. `中止する` が効くこと
7. 完了後、候補確認モーダルが開き、フォームへ適用できること
8. 保存まで通ること

失敗系も確認する。

- 連携設定でログアウト状態を作り、`連携設定を開く` 導線が出ること
- 文字も画像も取れないPDFで `貼り付けで入力` 導線が出ること

結果は `制作管理/makinglog.md` へ `[曹長(テスト分隊)] YYYY-MM-DD HH:MM JST` 形式で ✓/✗ と再現手順まで記録する。

## 4. 踏み抜きやすい罠（前任が実際に踏んだ / 回避した）

### 罠1: `vendor/bin/pint` はリポジトリ全体を整形する

引数なしで実行すると **179ファイル**が書き換わり、レビュー不能な差分になる。
実行後は、自分が触っていないファイルの整形を戻すこと。

```bash
# リポジトリルートで実行。自分の変更ファイルだけ mine に列挙する
git diff --name-only | grep '\.php$'
```

**注意: `.blade.php` も `.php` で終わる。** 単純な `.php$` フィルタで戻すとビュー変更まで消える（前任が実際に消した）。
対象ファイルのパスは**リポジトリルートからの相対**で指定すること（`bits-keep/` 配下で `git checkout` すると pathspec が合わない）。

### 罠2: 既存テストが1件失敗している

```
Tests\Feature\ComponentDetailRouteSmokeTest::specs route accepts tolerance value and returns master order
```

これは**本件の変更前から同一に失敗している既存の失敗**であり、本件起因ではない。
自分の変更のせいだと誤認しないこと。切り分けは以下で確認できる。

```bash
git stash push --include-untracked -- app config routes tests database/migrations resources
php artisan test --filter=ComponentDetailRouteSmokeTest   # 同じく失敗する
git stash pop
```

別件として調査するかは指示を仰ぐこと。

### 罠3: フロント未ビルドだとテストが大量に落ちる

Vite manifest がないと、画面描画系テストが**14件**まとめて落ちる。実装の問題と誤認しやすい。

```bash
npm run build   # 実行後に再テストすること
```

`public/hot` が存在したら削除する（`rm bits-keep/public/hot`）。

### 罠4: `--image` は複数値を取る

`codex exec` の `--image` は `num_args = 1..` のため、位置引数に解析指示を置くと**指示文が画像パスとして取り込まれる**。
現在の実装は解析指示を**標準入力**から渡すことで回避している。ここを引数へ戻さないこと。

### 罠5: 作業ディレクトリをアプリ配下にしない

`CODEX_WORKSPACE_ROOT` をリポジトリ配下に向けると、`AGENTS.md` / `CLAUDE.md` が読み込まれて解析プロンプトが汚染される。
実装側で検知して環境不備エラーにしているが、そもそも設定しないこと。

## 6. 設計の前提（勝手に変えないこと）

以下は意図をもって決めた設計であり、実装都合で崩さないこと。崩す必要が出たら**先にユーザーへ相談する**。

- **解析の入口は1本**。`データシートから自動入力` のみ。ボタン名・進行表示に解析エンジン名（Codex / Gemini / ChatGPT）を出さない。どこで解析するかは連携設定の運用設定であり、利用者に毎回選ばせない
- **解析はブラウザのタブ寿命に紐づけない**。画面を閉じても再読込しても解析は続き、戻れば続きが見える
- **応答本文から JSON を探索しない**。出力はスキーマで強制する。旧方式の不具合の温床がここだった
- **後段はエンジンで分岐させない**。正規化 → スペック詳細照合 → 分類推薦は全エンジン共通の1経路を通す
- **失敗は種別で扱う**。再実行が無意味な失敗で再実行を勧めない
- 旧方式（ChatGPTタブ解析 / 画面で待つ解析）は**併存させるが既定導線から降格**。利用者に使い分け判断を押し付けない
