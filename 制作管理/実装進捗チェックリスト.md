  - どう直すか: 接頭辞候補セットを `decimal_full=T/G/M/k/無印/m/u/n/p/f`、`decimal_non_fractional=T/G/M/k/無印`、`binary_iec=Ti/Gi/Mi/Ki` に分ける。スペック詳細編集UIでは `B` / `bit` / `bps` 系に `T/G/M/k/無印/Ti/Gi/Mi/Ki` を表示し、10進数系を選ぶと2進数系を、2進数系を選ぶと10進数系を自動で外す。`m/u/n/p/f` は Byte/bit 系の候補に出さず、`無印` は接頭辞グループ外の基準単位表示として共通許可する。

### 2-3b. データシート解析自動化（Tampermonkey + ChatGPT Web）

### 2-3c. 部品シリーズ・値展開管理
- [x] シリーズものと単体物の登録管理を分離する方針を実装する
  - なぜだめか: 抵抗器・コンデンサ・インダクタ・ツェナー・水晶のように値展開で管理したい部品と、IC・マイコン・センサのように型番単位で個別管理したい部品を同じ登録フォームだけで扱うと、シリーズ品は値違いの登録作業が膨らみ、単体物は不要な系列設定を見せられる。
  - どう直すか: 部品分類または部品登録導線に `series_management_mode` 相当の設計を追加し、UIでは `シリーズを使わない` `シリーズ登録も使う` `シリーズ登録を推奨` を選べるようにする。部品登録では `登録単位` で `単体` / `シリーズ` を切り替え、シリーズ登録時だけ既存の `部品シリーズ` と `シリーズ値` を選べるようにする。登録済みシリーズが0件の場合は空selectを出さず、`マスタ・利用設定 > 部品シリーズ` への導線を出す。通常の部品は従来通り `components` 正本、値展開部品は `部品シリーズ` 正本から必要な値だけ実部品化できるようにする。
- [x] `部品シリーズ` 正本と `値展開ポリシー` のDB設計を追加する
  - なぜだめか: 1kΩ、1.2kΩ、1.5kΩのような値違いを全て独立部品として登録すると、シリーズ名・メーカー・パッケージ・許容差・温度特性・仕入先情報が重複し、あとで一括修正できない。
  - どう直すか: `component_series` にシリーズ共通情報を持たせ、`component_series_value_policies` または同等カラムで値展開方式、基準スペック詳細、基準単位、基準系列、世代範囲、丸め規則を管理する。`component_series_values` には値、表示ラベル、単位、由来、除外状態、実部品化済み `component_id`、在庫対象かどうかを持たせる。
- [x] 値展開方式を `E系列` / `基準系列+追加値` / `任意値リスト` / `範囲/刻み` / `値展開なし` に分ける
  - なぜだめか: E12やE24を前提に固定すると、`E12で揃えているが一部だけE24が混在する` 抵抗・コンデンサ運用や、E系列に乗らないツェナー電圧、水晶周波数、ヒューズ電流、コネクタ極数が例外処理だらけになる。
  - どう直すか: `value_set_type` として `e_series` `hybrid_series` `custom_list` `range_step` `none` を持たせる。`hybrid_series` は `primary_series=E12` に `extra_series=E24` または手入力の `extra_values` を追加でき、`custom_list` は値をCSV/貼り付けで任意に持てるようにする。
- [x] E12基準に少量E24が混在する運用を通常ケースとして扱う
  - なぜだめか: 混在値を別シリーズに分けると、実際には同じ抵抗シリーズなのに検索・在庫・仕入先が分裂する。逆にE12以外を禁止すると、実棚に少量あるE24値を登録できない。
  - どう直すか: 値ごとに `origin=primary_generated / extra_series / manual / imported / supplier` と `source_series=E12/E24/...` を持たせ、画面では `E12` `E24追加` `手動` などの由来バッジで見せる。基準系列外の値も同じシリーズ内の値として保持し、一覧・検索・在庫では通常値として扱う。
- [x] E系列に乗らない部品向けの任意値リストを実装する
  - なぜだめか: ツェナー電圧、TVS電圧、水晶周波数、ヒューズ電流、コネクタ極数、LED色/波長のような値はE系列で生成できず、系列前提のUIではソート・重複判定・表示単位が崩れる。
  - どう直すか: `custom_list` は値・単位・表示ラベル・ソート値を明示入力できるようにする。例として `2.4V, 2.7V, 3.0V, 3.3V` のツェナー、`32.768kHz, 8MHz, 12MHz, 16MHz` の水晶、`0.5A, 1A, 2A` のヒューズ、`2P, 3P, 4P` のコネクタを破綻なく保存できるテストデータを用意する。
- [x] シリーズ管理UIと値マトリクスを追加する
  - なぜだめか: 値展開をDBだけ持っても、ユーザーがどの値を持っていて、どれが候補だけで、どれが例外追加なのかを見られないと運用できない。
  - どう直すか: 部品シリーズ画面に `値展開方式`、基準系列、追加値、除外値、任意値リストを編集する領域を作る。値マトリクスには `値` `由来バッジ` `実部品化` `在庫` `パッケージ` `許容差` `温度特性` `仕入先` `メモ` を並べ、CSV貼り付け、値追加、値除外、選択値の一括部品化を用意する。
- [x] 仮想値と実部品を分離し、在庫・検索・部品一覧へ反映する
  - なぜだめか: シリーズ上の候補値をすべて部品一覧に出すと、持っていない値まで現物のように見える。逆に実部品化した値だけをシリーズに残すと、値展開の見通しや追加登録の支援が弱くなる。
  - どう直すか: `component_series_values` は仮想値として保持し、在庫・仕入先・画像・データシートを持つ段階で `components` へ実部品化する。部品一覧は既定で実部品のみ表示し、シリーズ詳細では仮想値を含む全値を見せる。検索では `実部品のみ` `シリーズ候補も含む` を明示的に切り替える。
- [x] 既存の抵抗器・コンデンサ等を部品シリーズへ移行する手順を作る
  - なぜだめか: 現在の個別部品データをいきなりシリーズ前提へ切り替えると、同名・同値・同パッケージの重複や、在庫付き部品の紐付け漏れが起きる。
  - どう直すか: 移行前に同一メーカー・シリーズ名・部品分類・パッケージ・許容差・温度特性で候補グルーピングし、値スペックを `component_series_values` へ抽出する。自動判定できないものは確認リストへ出し、在庫や仕入先を持つ既存 `components` は実部品化済み値としてリンクする。
- [x] 部品シリーズ導入時のAPIと権限設計を追加する
  - なぜだめか: シリーズ値の一括生成・CSV貼り付け・一括部品化は影響範囲が広く、通常の部品1件編集と同じ権限・監査ログでは追跡が弱い。
  - どう直すか: `GET/POST/PATCH /api/component-series`、値展開プレビュー、一括値保存、一括実部品化のAPIを分ける。作成・編集・一括部品化は editor 以上、削除/アーカイブや大量除外は admin 確認を基本にし、変更前後の値リストを audit log に残す。
- [x] シリーズ展開のテストケースを追加する
  - なぜだめか: 値展開は見た目が合っていても、丸め、重複、追加値、除外値、単位変換、実部品化で壊れやすい。特に `E12基準 + 少量E24` と `非E系列` をテストしないと、実運用の懸念が再発する。
  - どう直すか: E12基準に `1.1kΩ` などE24由来の追加値を混ぜても同一シリーズ内で保存・表示・検索できること、ツェナー電圧・水晶周波数・ヒューズ電流・コネクタ極数の任意値リストがE系列生成に依存せず保存できること、仮想値と実部品の一覧表示が分離されること、CSV貼り付けと値除外が重複を作らないことを Feature/Unit テストで固定する。
