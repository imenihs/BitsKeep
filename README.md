## 概要

BitsKeep は個人事業・小規模法人向けの電子部品管理システムです。部品の登録・在庫追跡・発注・案件紐付けをブラウザ上で一元管理します。

**アクセス URL:** https://bits-keep.rwc.0t0.jp/

---

## 機能一覧

| 機能 | 説明 |
|---|---|
| 部品管理 | スペック・画像・データシート・仕入先を登録。フリーワード・部品分類・スペック範囲で検索 |
| 在庫管理 | 入庫・出庫・在庫履歴。棚卸しモードで実数と差分を管理 |
| 発注管理 | 在庫警告から発注リストを作成し、商社別 CSV で出力 |
| 案件管理 | 案件と使用部品の紐付け。Notion との双方向同期 |
| 保管棚管理 | 棚のグループ管理・廃止・復元 |
| 商社管理 | 仕入先・単価・リードタイム・送料無料閾値 |
| マスタ管理 | パッケージ分類・パッケージ詳細・部品分類・スペック詳細・スペック候補設定・共通スペック詳細・許容差スペック詳細・入力テンプレートの管理 |
| 部品比較 | 最大5部品の仕様・価格を横並び比較（差分ハイライト） |
| Altium 連携 | SchLib/PcbLib 登録・部品詳細からシンボル/フットプリント紐付け |
| 設計ツール | 抵抗/容量ネットワーク探索・エンジニアリング計算補助・設計解析ツールハブ |
| ユーザー管理 | 招待メール・ロール設定（管理者/編集者/閲覧者） |
| 操作ログ | 全 CRUD 操作の変更差分を記録・フィルタ閲覧 |
| CSV インポート | テンプレート形式で部品データを一括登録 |
| データのバックアップ | 現在の登録データを保存し、バックアップファイルから復元 |

## はじめる前に

### ログインとアカウント

管理者から招待メールが届いたら、メール内のリンクからパスワードを設定してログインします。

### 権限

ログイン後、ヘッダ右上に自分の権限バッジが表示されます。

| 表示 | できること |
|---|---|
| 管理（赤枠） | すべての操作 |
| 編集 | 部品・在庫・案件の登録・編集 |
| 閲覧 | 一覧・詳細の参照のみ |

権限を変更したい場合は管理者に連絡してください。

### 最初にやること

BitsKeep を使い始める前に、以下のマスタを登録してください。部品登録時にこれらが必要になります。

1. **部品分類を登録する** — 「マスタ管理 → 部品分類」で「抵抗」「コンデンサ」「FPGA」などを追加
2. **パッケージ分類とパッケージ詳細を登録する** — 「マスタ管理 → パッケージ分類」で「SMD」「THT」を追加し、その配下に「0402」「SOT-23」などを追加
3. **部品分類ごとのスペック詳細を登録する** — 「マスタ管理 → 部品分類」で入力候補の親を用意し、「マスタ管理 → スペック詳細」で「静電容量」「耐圧」などを追加。必要に応じて英語名・記号・別名・標準単位も設定
4. **商社を登録する** — 「商社管理」で仕入先を追加
5. **保管棚を登録する** — 「保管棚管理」で棚を追加

## ダッシュボード

ログイン後の起点となる画面です。

### 今日の確認事項

- **在庫警告件数** — 発注点を下回った部品の件数。クリックで在庫警告画面へ
- **最近アクセスした部品** — 直近で開いた部品へのショートカット

### グローバル検索

**Ctrl+K**（Mac は Cmd+K）でどのページからでも検索ランチャーを起動できます。型番・通称でインクリメンタル検索し、Enter で詳細ページへ移動します。

### 業務別メニュー

ダッシュボード下部に「在庫入力」「在庫警告」「案件管理」などのショートカットが並んでいます。よく使う操作は並び替えて保存できます（ヘッダ右上「ホーム設定」）。

## 部品管理

### 部品を登録する

「部品一覧」→ 右上「+ 新規登録」から登録画面を開きます。

#### 入力項目

| 項目 | 必須 | 説明 |
|---|---|---|
| 型番 | ✓ | メーカー型番。重複チェックあり |
| 名称 | | 通称・社内管理名 |
| メーカー | | 製造元名 |
| 入手可否 | | 量産中 / EOL / 在庫限り / 非推奨 |
| 部品分類 | | 複数選択可。事前登録が必要（[マスタ管理](#マスタ管理)） |
| パッケージ分類 | | 大分類を選ぶとパッケージが絞り込まれる |
| パッケージ | | 0402・SOT-23 など |
| 代表保管棚 | | この部品を通常置く棚（[保管棚管理](#保管棚管理)で事前登録が必要） |
| 登録単位 | | `単体` / `シリーズ`。シリーズを選ぶ場合は `部品シリーズ` と `シリーズ値` を選び、登録部品をシリーズ値へ紐づける |
| スペック | | `部品分類` で候補を絞り、`スペック候補` で1行追加、`入力テンプレート` の `一式追加` で複数行を追加する。値種別は `TYP`、`MIN-MAX`、`≤MAX`、`≥MIN`、`Min/Typ/Max` から選ぶ。入力中は `入力値` と `標準単位換算` を確認できる。候補にないスペック詳細は部品分類が一意に決まる場合だけ行内の「+」から追加可能 |
| 仕入先 | | 商社・商社型番・単価・購入単位・価格ブレーク。複数追加可 |
| 部品画像 | | jpg/png/webp、5MB まで |
| データシート | | PDF ファイル。複数添付可。各PDFに表示名を付けられる |
| カスタムフィールド | | 任意のキーと値を自由に追加 |

#### スペック詳細の選択

部品登録と部品詳細のスペック編集は、説明カードではなく構造で操作対象が分かるUIにします。

1. `部品分類` select で、マスタ上の部品分類または `フィルタしない` を選びます。部品詳細のスペック編集では、現在の部品分類を初期選択します。
2. `スペック候補` dropdown は選択中の部品分類で絞り込まれ、`追加` で1行を登録済みスペックへ追加します。
3. `入力テンプレート` dropdown は選択中の部品分類に紐づくテンプレートだけを出し、`一式追加` でテンプレート内の行をまとめて追加します。
4. テンプレート選択時は `[ピーク耐圧 V_RRM]` のように、実際に一括追加されるスペック詳細の日本語名と略号をチップでプレビューします。単なる「x項目」表示だけにはしません。
5. 追加済みの行は下部の `登録済みスペック` に並べ、値・単位・入力形式を編集します。既に同じスペック詳細がある行は重複追加しません。

部品詳細のスペック編集からは、選択中の部品分類を引き継いで `スペック詳細`、`スペック候補設定`、`共通スペック詳細`、`許容差スペック詳細`、`入力テンプレート` の各マスタへ移動できます。行内の `+` は選択中の部品分類に個別スペック詳細を作るショートカットです。同名の既存スペック詳細がある場合は新規作成せず、選択中部品分類の候補へ追加してから行に紐づけます。共通・許容差・テンプレートの設計変更はマスタ管理側で行います。

#### 保存

フォーム上部と下部に「保存」ボタンがあります。長いフォームを下まで入力した後、画面を上に戻らなくても保存できます。

#### データシート解析補助

現状の部品登録では、データシートからの補助入力に次の 3 系統があります。

- `ChatGPTで自動入力` — Tampermonkey userscript 経由で `PDF選択 -> 一時アップロード -> ChatGPT Web 解析 -> レビュー` まで自動化
- `ChatGPTから貼り付け` — ChatGPT で PDF を読ませた結果 JSON を貼り付けてレビューする
- `Geminiで解析` — 外部解析サービスの利用を許容する環境だけの任意導線

解析レビューでは部品分類候補を既存部品分類へ紐付けると、その部品分類に対応する候補スペック詳細と入力テンプレート候補が表示されます。テンプレートを選ぶとレビュー中のスペック候補へ行を追加し、内容を確認してからフォームへ適用できます。

どちらの導線でも、解析後はいったんレビュー用モーダルが開きます。ここで次を確認・修正してからフォームへ適用します。

- 基本情報: `型番` `メーカー` `通称` `説明`
- 部品分類候補: 解析結果の複数候補から、既存の部品分類へ紐付けて選択
- パッケージ候補: 解析結果の複数候補から、既存の `パッケージ分類 / パッケージ詳細` へ紐付けた 1 件を選択
- スペック候補: 日本語名・英語名・記号・別名を使って既存スペック詳細へ照合し、未一致項目はレビュー画面の「+」から追加、削除

データシート上の元表記は `データシート表記` として確認用に表示され、保存時は既存のスペック詳細へ紐付けます。表記ゆれはスペック詳細の別名として管理します。

`ChatGPTで自動入力` は `Tampermonkey` userscript を前提に、`PDF選択 -> BitsKeepへ一時アップロード -> ChatGPT Web 解析 -> 結果レビュー -> 保存` を自動化します。自動化に失敗した場合は、同じ画面から `ChatGPTから貼り付け` へ即切り替えられます。応答テキストのコピー補助もあるため、ChatGPT画面の変更やログイン切れが起きても手動貼り付けへ切り替えられます。

Tampermonkey連携が未接続でも、部品登録画面を開いただけでは案内モーダルを自動表示しません。`ChatGPTで自動入力` などの解析操作を押した時だけ、導入・更新・手動貼り付けへの切替案内を表示します。

#### Tampermonkey 導入手順

1. `https://bits-keep.rwc.0t0.jp/tampermonkey/bitskeep-chatgpt-helper.user.js` を Tampermonkey へインストールする
2. `https://bits-keep.rwc.0t0.jp/*` と `https://chatgpt.com/*` への実行を許可する
3. ChatGPT にログインした状態で BitsKeep の部品登録画面を再読込する
4. PDF を選択して `ChatGPTで自動入力` を押す
5. 自動化が失敗したら案内モーダルから `ChatGPTから貼り付け` へ切り替える

#### userscript 更新手順

1. 部品登録画面の `ChatGPT自動解析` モーダルから `userscript を更新` を押す
2. Tampermonkey の更新確認画面で `再インストール` または `更新` を承認する
3. `再読込して反映` を押して部品登録画面へ更新版 userscript を反映する
4. 再読込後に連携成功トーストが出れば更新完了。旧版のままなら更新ダイアログが再表示される

`userscript を更新` 導線はキャッシュ回避クエリ付き URL を開きます。さらに userscript 自体にも `@downloadURL` / `@updateURL` を埋め込み、Tampermonkey 側の更新元を固定しています。

#### 一時PDFの扱い

- ChatGPT 自動入力で選択した PDF は一時保存され、署名付き URL で ChatGPT タブへ渡されます
- 一時PDFの有効期限は 2 時間です
- 部品保存が成功すると一時PDFは正式なデータシートへ確定され、使い終わった一時リンクは再利用できません
- キャンセル時は BitsKeep 側で一時PDFを破棄します

### 既存部品を複製して登録する

同じメーカーの別型番など、似た部品を素早く登録できます。

1. 複製元の部品詳細ページを開く
2. 「複製」ボタンをクリック
3. 型番など差分だけ修正して「保存」

### 部品を探す

#### 基本検索

部品一覧の上部にある検索バーで型番・名称・メーカーをキーワード検索できます。

#### 詳細フィルタ

「詳細条件」を開くと以下の条件で絞り込めます。

- 部品分類（複数選択可）
- 入手可否
- メーカー
- パッケージ分類 / パッケージ
- スペック詳細 + 値の範囲（例: 静電容量 100nF〜10μF）
- 在庫状態（在庫あり / 在庫切れ / 警告中）
- 購入日の範囲

フィルタを適用した状態は「フィルタチップ」として表示され、1クリックで個別に解除できます。

#### お気に入り

部品カードの星アイコンでお気に入り登録できます。「お気に入りのみ」フィルタで一覧を絞り込めます。

#### 並び順

既定は部品分類、パッケージ分類、パッケージ、型番の順に並ぶ台帳向け表示です。型番内の数字は自然順で扱うため、`2SC945` は `2SC1815` より前に並びます。必要に応じて更新順、通称順、型番順へ切り替えできます。

### 部品を比較する

1. 部品一覧でカード左上のチェックボックスを選択（最大5件）
2. 画面下部に表示される「比較」ボタンをクリック
3. 比較画面でスペック・価格・在庫を横並びで確認

差分がある行はハイライト表示されます。「差異のある行のみ表示」チェックで絞り込めます。

### 部品詳細

部品詳細ページでは以下の情報を確認・操作できます。

- 基本情報・スペック・仕入先・画像・データシート
- 在庫数（新品 / 中古 別）と保管棚
- **入庫 / 出庫** ボタン（[在庫管理](#在庫管理)）
- 在庫履歴（入出庫のログ）
- 関連案件（この部品を使っている案件一覧）
- 類似部品（同じ部品分類・パッケージの部品候補）
- Altium リンク（シンボル名・フットプリント名）

## 在庫管理

### 入庫する

#### 部品詳細から入庫

1. 部品詳細ページ → 右上「入庫」
2. 以下を入力して「確定」

| 項目 | 説明 |
|---|---|
| 数量 | 入庫する個数 |
| 区分 | 新品 / 中古 |
| 保管棚 | 置く棚（複数棚への分配も可） |
| ロット番号 | 任意 |
| 備考 | 任意 |

#### 在庫入力画面からまとめて入庫

複数部品をまとめて入庫する場合はこちらが便利です。

1. ダッシュボード「在庫入力」または全機能一覧 →「在庫入力」
2. 部品を検索して追加
3. 各部品の数量・棚を入力
4. 「一括登録」で確定

### 出庫する

1. 部品詳細ページ →「出庫」
2. 数量・用途・備考を入力して「確定」

在庫が足りない場合はエラーが表示されます。

### 在庫履歴を確認する

部品詳細ページ下部の「在庫履歴」セクションに入出庫のすべてのログが表示されます。日時・操作者・数量・棚・備考を確認できます。

### 在庫警告

発注点（`min_stock`）を下回った部品は自動的に在庫警告として検出されます。

- ダッシュボードの警告バッジで件数を確認できます
- 全機能一覧 →「在庫警告」で一覧を確認できます

発注点は部品登録・編集画面の「在庫下限」フィールドで設定します。

### 棚卸しをする

実際の在庫数とシステムの在庫数を照合・修正します。

1. 「保管棚」→ 右上「棚卸しモード」をオン
2. 画面上部のオレンジのバーが表示されます（棚卸し中の目印）
3. 各棚の「実数」欄に実際の在庫数を入力（現在の在庫数がデフォルト表示）
4. 差分（±）がリアルタイムで表示されます
5. 「確定」で保存 — 差分が在庫に反映されます

棚卸しモード中は「棚卸しモード終了」ボタンで確定せずに終了できます。

## 発注管理

### 在庫警告を確認する

全機能一覧 →「在庫警告」で発注点を下回った部品の一覧を表示します。

各行には以下の情報が表示されます。
- 型番・通称
- 現在の在庫数（新品 / 中古）
- 発注点との差分
- 発注済みで納品待ちの件数

### 発注リストを作る

1. 在庫警告画面で発注したい部品にチェックを入れる
2. 「発注リストへ追加」ボタンをクリック
3. 発注画面（全機能一覧 →「発注画面」）に部品が追加される

### 発注画面で内容を決める

発注画面では各部品について以下を設定します。

| 項目 | 説明 |
|---|---|
| 購入単位 | バラ / テープ / トレー / リール / 箱 |
| 購入数量 | 発注する個数 |
| 購入商社 | 仕入先を選択。選択すると商社型番と単価が自動入力される |

### 商社別 CSV を出力する

「〇〇商社 をCSV出力」ボタンで、その商社向けの発注シートを CSV で書き出します。

CSV の列: 型番 / 通称 / パッケージ / 購入単位 / 商社 / 商社型番 / 数量 / 単価 / 小計

## 案件管理

### 案件を作成する

1. 全機能一覧 →「案件管理」→「+ 案件を追加」
2. 案件名・事業（Notion 事業 DB と紐付く）を入力して保存

### 使用部品を追加する

案件詳細ページの「使用部品」セクションで部品を検索して追加します。使用数も合わせて記録できます。

### Notion 同期

「連携設定」で Notion API トークンと事業データベース ID を設定すると、Notion 上の案件データを BitsKeep に同期できます。

- 同期は「案件管理」画面の「同期」ボタンで手動実行します
- 同期結果（成功 / 失敗 / 件数）が画面上に表示されます
- Notion で作成した案件は `origin: Notion` として取り込まれます

Notion 連携の設定方法は [Notion 連携設定](#notion-連携設定) を参照してください。

## 保管棚管理

### 棚を登録する（管理者のみ）

1. 「保管棚」→「+ 棚を追加」
2. 以下を入力して保存

| 項目 | 説明 |
|---|---|
| 棚コード | 識別コード（例: A-01） |
| 棚名称 | 表示名 |
| グループ | 棚のグループ名（例: メインラック、引き出し） |
| 並び順 | 一覧での表示順 |
| 備考 | 任意 |

### 棚を廃止する

使わなくなった棚は「廃止」にすると選択候補から消えます。在庫データへの影響はありません。管理者は「復元」でいつでも元に戻せます。

## マスタ管理

部品登録に必要な部品分類・パッケージ詳細・スペック詳細・候補設定・入力テンプレートを管理します。

マスタ管理のタブは URL の `tab` クエリで保持されます。例: `/master?tab=packages`、`/master?tab=spec-types`。タブ移動後にリロードしても同じタブで開き、ブラウザの戻る/進むでもタブ状態が追従します。スペック系は `部品分類`、`スペック詳細`、`スペック候補設定`、`共通スペック詳細`、`許容差スペック詳細`、`入力テンプレート` に責務を分け、入力テンプレートは一番右に置きます。

スペック系タブの左ペインは部品分類を選ぶための領域に限定し、分類名の横にそのタブで扱う登録数を小さく `登録:4個` のように表示します。選択後の右ペインのヘッダでは、`個別`、`入力候補`、`共通`、`許容差`、`テンプレート`、`行` など、そのタブの文脈に合う短い件数バッジで内訳を確認します。

### 部品分類

「抵抗」「コンデンサ」「FPGA」など部品の種類を表すタグです。部品には複数の部品分類を付けられます。部品分類はスペック詳細の候補と入力テンプレートの親でもあります。

- 一覧はドラッグ&ドロップで表示順を変更できます
- 使わなくなった部品分類は「アーカイブ」で候補から外せます（部品への紐付けは残ります）

### 部品分類と候補スペック詳細

`部品分類` は部品そのものに付ける種類・検索タグであり、スペック詳細の候補・並び順・既定値を束ねる入力候補グループでもあります。

例: 部品分類が `BJT` のとき、その中に `VCEO`、`コレクタ電流`、`hFE`、`fT` などの候補スペック詳細を並べます。

### 部品シリーズ

抵抗・コンデンサ・インダクタなど、同一シリーズの中に値違いが大量にある部品は、単体部品を1件ずつ並べるのではなく、`部品シリーズ` とシリーズ値一覧で扱います。一方で IC・MCU・センサ・モジュールなど、型番ごとの差分が大きい部品は従来通り単体部品として管理します。

部品分類には `シリーズを使わない`、`シリーズ登録も使う`、`シリーズ登録を推奨` の扱いを設定できます。

部品登録画面では `登録単位` で `単体` と `シリーズ` を切り替えます。通常の部品は `単体` のまま登録し、シリーズ値から登録部品を作る場合だけ `シリーズ` を選んで `部品シリーズ` と `シリーズ値` へ紐づけます。
登録画面の `シリーズ` は既存シリーズへの紐づけ専用で、その場では部品シリーズを新規作成しません。登録済みシリーズがない場合は `部品シリーズ未登録` と表示し、`マスタ・利用設定 > 部品シリーズ` へ移動して先にシリーズ値一覧を作成します。

値展開方式は E系列だけに固定しません。シリーズごとに次の方式を選べるようにします。

- `E系列`: E12 / E24 / E96 などの標準系列から値を生成する
- `基準系列 + 追加値`: E12 を基準にしつつ、一部だけ E24 の値を追加するような混在を正式に扱う
- `任意値リスト`: ツェナー電圧、水晶周波数、ヒューズ電流、コネクタ極数など、E系列に乗らない値を手入力・CSV貼り付けで持つ
- `範囲/刻み`: ピン数や定格電流のように、一定範囲を刻みで展開する

部品シリーズでは、部品分類を選ぶと `スペック詳細` の候補をその部品分類に絞ります。単位は選択したスペック詳細の標準単位を自動で使い、シリーズ側では直接編集しません。パッケージは `パッケージ分類` を選んでから `パッケージ詳細` を選びます。

E系列は `開始値` / `終了値` を実数で入力します。使える接頭語は選択したスペック詳細の `入力候補接頭辞` に従います。例: 容量スペックで `u/n/p/f` が候補なら `1fF`、`10pF` のように入力できます。0ΩはE系列の値ではないため、`0を含む` チェックで追加します。`範囲/刻み` はこれとは別方式で、開始値・終了値・刻み幅を同じ接頭語ルールで入力します。

シリーズ値一覧では、まだ部品として登録していない値と、登録済みの値を分けて表示します。`選択値を部品化` は保存済みで未部品化の値をチェックした時だけ実行できます。シリーズ全体の候補値は広く持ちつつ、実際に使う値だけを部品として登録して在庫・価格・保管棚を管理することで、E12中心に少量のE24が混ざる運用や、E系列外のツェナー・水晶でも破綻しにくくします。

既存部品を移行する場合は、同一メーカー・シリーズ名・部品分類・パッケージ・許容差で候補をグルーピングし、値違いの候補一覧を作ります。在庫や仕入先を持つ既存部品は削除せず、該当するシリーズ値へ紐づけます。自動判定できない部品は確認リストで手動リンクします。

設計解析ツールの結果は、案件・部品・BOMの行番号や識別名を付けて保存できます。設計解析画面では登録部品からスペック値を読み込んで解析入力へ反映し、保存済み解析との差分比較や、MCU ADC入力・3.3V電源・I2Cバス・TVS保護のテンプレート複製保存もできます。

### パッケージ分類・パッケージ詳細

パッケージは2階層で管理します。

- **パッケージ分類**（例: SMD、THT）— 大分類
- **パッケージ詳細**（例: 0402、0603、SOT-23）— パッケージ分類に属する個別形状

部品登録時はパッケージ分類を選んでからパッケージを選びます。
パッケージ詳細の外形寸法は `X / Y / Z` の3値で持ちます。`X` は縦または長手方向、`Y` は横または幅、`Z` は実装高さです。画面ではこの意味をラベルで明示します。

### スペック詳細

「静電容量」「耐圧」「周波数」など、検索・比較したい仕様項目を定義します。スペック詳細には **日本語名 / 英語名 / 記号 / 別名 / 標準単位** を設定できます。

- 日本語名は画面表示と標準検索名に使います
- 英語名・記号・別名は、英語データシートや略記号から同じスペック詳細へ照合するために使います
- 同じ日本語名のスペック詳細を複数登録できます。例: `電源電圧` を `VDD` と `VCC` で別々に持つ場合は、記号・別名で区別します
- `スペック詳細` タブでは先に部品分類を選び、その部品分類に持たせるスペック詳細を追加・編集・アーカイブします
- スペック詳細は `抵抗値` `耐圧` のように、選択中の部品分類でよく使う仕様項目です。ほかの部品分類でも使いたい項目は、`共通スペック詳細` か `許容差スペック詳細` から候補に入れます
- 共通スペック詳細は「共通スペック詳細」タブで左の部品分類を選び、登録済みの共通スペック詳細から、その部品分類の入力候補に入れるものを選びます
- スペック候補設定タブの行 `編集` は、候補側の範囲・扱い・既定の入力形式・既定単位・メモだけを編集します。名称・記号・別名・単位などスペック詳細そのものの編集は、各スペック詳細タブの `編集` で行います
- スペック候補設定タブで候補へ追加するときは、`スペック詳細から追加`、`共通スペック詳細から追加`、`許容差スペック詳細から追加` の3系統から既存項目を選びます。このタブではスペック詳細の新規作成やフリー入力を開きません
- スペック候補設定タブの候補追加・候補設定編集・候補順のドラッグ&ドロップは操作完了時に自動保存します。上下ボタンでの並び替えは使いません
- 許容差スペック詳細は、通常の共通スペック詳細とは兄弟の別棚として管理します。左の部品分類を選び、登録済みの許容差スペック詳細から、その部品分類の入力候補に入れるものを選びます。通常/許容差を切り替えるラジオや、許容差タブ内の行別 `許容差` バッジは置きません
- 許容差スペック詳細の例: `抵抗値許容差 ±5%`、`容量許容差 B級 ±0.1pF`、`容量許容差 Z級 +80/-20%`、`抵抗温度係数 ±100ppm/℃`、`容量温度特性 X7R`
- 記号は HTML ではなく `h_FE` `V_CBO` `V_CE-(sat)` のように保存します。`_` は下付き、`~` は上付き、`-` は通常表示へ戻す区切りです
- 標準単位は 1 つだけ設定します（例: 静電容量 → F、電流 → A）
- 接頭辞候補と表示接頭辞はスペック詳細ごとに設定できます。`B` / `bit` / `bps` 系は 10進接頭辞（`T/G/M/k/無印`）または IEC 接頭語（`Ti/Gi/Mi/Ki`）を選びます。一方を選ぶともう一方は自動で外れ、`m/u/n/p/f` は候補から外します

### 入力テンプレート

入力テンプレートは、部品分類ごとにスペック行をまとめて追加する初期行セットです。候補スペック詳細の所属・並び順・既定値は `スペック候補設定` タブ、入力テンプレートは `入力テンプレート` タブで編集します。テンプレート行で選べるスペック詳細は、関連する部品分類の候補スペック詳細だけに絞ります。`共通` は部品分類として表示・選択せず、共通スペック詳細として管理します。

マスタ管理の追加・編集・候補選択系モーダルは内容量に合わせて幅を分けます。候補追加や入力テンプレート編集など一覧・行編集が必要なものは `modal-master`、パッケージ詳細とスペック詳細・共通スペック詳細・許容差スペック詳細・パッケージ分類・部品分類・候補設定編集は `modal-md`、確認ダイアログは短文専用の小幅モーダルとして扱います。

マスタ管理の並び順は、編集モーダルで数値を入力させません。パッケージ分類、パッケージ詳細、部品分類、候補スペック詳細の並び替えは、一覧上のドラッグ&ドロップで行います。`sort_order` は内部の保存値であり、ユーザーが直接調整する項目として表示しません。

マスタ本体を使わなくする操作は `アーカイブ`、候補関係の解除は `候補から外す` と表示します。`候補から外す` はスペック詳細そのものを削除する操作ではありません。候補から外す操作だけは確認ダイアログを挟みます。

部品登録時の表示単位は、基準単位から自動で人間向けに読みやすい接頭語へ寄せます。例:

- `0.000001 A` は `1uA`
- `1000 Ω` は `1kΩ`
- `0.000000005 s` は `5ns`
- `1MB` は `1000000 B`、`1MiB` は `1048576 B`、`512KiB` は `524288 B` として扱います。`1Mbit` と `1Mbps` はどちらも10進の `M` として正規化します

登録画面ではスペック行に自由な「名前」欄はありません。必ずスペック詳細を選び、候補にない場合だけその場の追加モーダルでスペック詳細を登録します。値種別は `TYP`（代表値）、`MIN-MAX`（範囲）、`≤MAX`（最大のみ）、`≥MIN`（最小のみ）、`Min/Typ/Max` の5種を扱えます。検索用の数値は常に標準単位へ換算して行うため、`1uA` と `1e-6A` は同じ値として扱われます。

UI表示名は `部品分類` / `パッケージ詳細` / `スペック詳細` / `スペック候補設定` / `候補スペック詳細` / `入力テンプレート` / `共通スペック詳細` / `許容差スペック詳細` に整理しています。内部名の対応は API リファレンスと仕様書で管理します。

## 設計ツール

### 抵抗/容量ネットワーク探索

「全機能一覧 → 設計ツール → 抵抗/容量ネットワーク探索」で、抵抗/容量ネットワーク、分圧、可変抵抗の計算を同じ画面で扱います。

- 画面の上位タブは `ネットワーク探索` / `分圧` / `可変抵抗` です
- `ネットワーク探索` タブは抵抗/容量ネットワーク探索専用で、分圧UIは置きません。抵抗とコンデンサで直列・並列の合成式を切り替え、直並列混在候補も表示します
- `分圧` タブでは `分圧` と `VR分圧` のサブモードを切り替えます。`分圧` は2抵抗分圧、`VR分圧` は `Vin -> R上 -> VR -> R下 -> GND` のワイパ出力範囲設計です
- 分圧は従来の目標比率指定に加え、入力電圧 Vin と出力電圧 Vout から `Vout / Vin` の目標比率を直接計算できます
- 通常分圧は負荷条件を指定できます。抵抗負荷は出力からGNDへの抵抗で、`∞` は無負荷です。電流負荷は出力から引き抜く電流で、`0A` は無負荷です。電流負荷の計算には Vin が必要です
- 無負荷の指定は手入力前提にせず、抵抗負荷は `∞` ボタン、電流負荷は `0A` ボタンで設定できます。この操作は `分圧` と `VR分圧` の両方で使えます
- 分圧候補は R1/R2、実比率、負荷込み出力電圧、合計抵抗範囲、誤差をまとめて表示
- E6/E12/E24/E48/E96、任意値、在庫部品を候補集合にできます
- 在庫限定では、電圧や許容差ではなく抵抗値/容量値のスペックを優先して使います
- ネットワーク探索の1〜2素子と分圧タブの候補はE系列全体を使い、3素子以上または直並列混在は探索量上限に達した場合に途中候補と次アクションを表示します
- 探索できない条件、候補プール数、打ち切り有無、非網羅探索条件、次アクションを結果に表示します
- 画面では候補の簡易回路表示、比較トレイ、在庫リンク、可変抵抗 + 固定抵抗の標準値候補選定を扱います
- 可変抵抗設計は `基準抵抗値` + `可変幅` で要求範囲を作ります。可変幅は `%` と `Ω` の両方を指定でき、`%` は基準抵抗値に対する幅として扱います
- 基準位置は `上限基準` / `中心基準` / `下限基準` から選びます。既存互換は `上限基準` で、例として `10kΩ, 20%` は `8kΩ〜10kΩ` になります
- 可変抵抗設計は算術上の理想値と採用候補を分け、`8kΩ` のような理想値だけを固定抵抗の採用結果として表示しません
- 現実装の採用候補は固定抵抗のE系列値、可変抵抗の標準VR値、カスタム値に限ります。在庫や購入リンクに紐づいていない候補は購入可能とは言いません
- 固定抵抗の標準値化で要求範囲を満たせない場合は、VRを範囲側に補正して固定抵抗を再計算します。直列はVR値を要求幅以上に上げ、並列は低端側を満たせるVRと固定抵抗を再計算します
- 可変抵抗 + 固定抵抗の候補には端点結果、目標下限/上限との差、固定抵抗/VRの補正有無、可変抵抗の標準値、CHECK/WARN判定を表示します。在庫/購入リンク未連携のためPASSは出さず、範囲包含する標準値候補はCHECK、範囲不足はWARNにします
- `VR分圧` は、Vin、出力下限/上限、指定した基準VR値から R上/R下 の固定抵抗候補を出します。基準VR値は緩い優先条件ではなく設計で使うVR素子の公称値として固定し、`10kΩ` 指定時に `200Ω` のような大きく異なるVR値は採用しません。通常分圧と同じ負荷条件を指定でき、負荷込みでワイパ端点の出力を計算します
- 現実装は公称値と無負荷/指定負荷モデルでの探索です。抵抗許容差、温度係数、VRワイパ抵抗、電力、コンデンサのDCバイアス/ESR、負荷の動的変動は別途確認してください。設計確認が残る候補は `PASS` にせず `CHECK` / `WARN` で表示します

### エンジニアリング計算

「全機能一覧 → 設計ツール → 計算」で各種電子回路計算補助ツールを使えます。

- SI 接頭辞（p/n/u/m/k/M/G/T）と PC 系接頭辞（Ki/Mi/Gi/Ti）を式中で使えます
- 複素数は `j` 表記で入力でき、直交形式と極座標（deg/rad）を確認できます
- 進数表示は 2進/8進/10進/16進、ビット幅、signed/unsigned を切り替えられます
- `solve(10=1/((1/x)+(1/20)), x)` のような方程式近似解、ユーザー定義関数、配列集計、色コード、日時差分を扱えます
- 関数一覧、補完候補、構文表示、履歴、固定式、結果コピーを備えます

### 設計解析ツールハブ

「全機能一覧 → 設計ツール → 設計解析ツール」で、ADCスケーリング、電解コンデンサ寿命、分圧/NTC、電流検出、電源余裕、比較器、熱設計、インタフェース、誤差/歩留まり、周波数応答、保護協調、ロジックIC参照、コネクタ視点補助、ケーブル判定、0Ω/未実装/ジャンパ整理、起動診断を同じ画面で確認できます。

- 各ツールは `基本条件 / 最悪条件 / 部品定格 / 出力・保存` に分けた入力欄を持ちます
- 結果は `PASS / WARN / FAIL / CHECK`、支配要因、不足条件、次アクション、コピー用サマリを返します
- 条件不足のTVS、ヒューズ、保護協調、推定熱抵抗を含む寿命計算などは `PASS` にせず、`CHECK` と不足条件を返します
- ロジックIC参照は 74HC/HCT/4000B 系の静的候補を返し、VIH/VIL、VOH/VOL、出力電流、速度、温度範囲はデータシート確認項目として残します
- コネクタ/ケーブル/ジャンパ系は、mating face/solder side、Pin1、量産初期値、BOM注記、重複Ref、未定義状態を確認できます
- 登録部品の `10kΩ`、`0.1uF`、`50mV` などの単位付きスペックは接頭辞を解釈して入力へ取り込みます
- 登録部品を指定すると、そのスペック値を解析入力へ取り込めます
- 結果カードには部品候補・在庫候補・部品詳細へのリンクが付きます
- 解析条件は案件、部品、BOMの行番号や識別名を付けて保存でき、保存済み解析との再計算・差分比較ができます
- MCU ADC入力、3.3V電源、I2Cバス、TVS保護の解析テンプレートを入力へ反映またはユーザー/案件単位で複製保存できます

## 困ったときは

| 困りごと | 参照先 |
|---|---|
| 部品が見つからない | [「部品を探す」](#部品を探す)の詳細フィルタでメーカー・パッケージ・スペック範囲を試す |
| 在庫数が実物と合わない | [「在庫履歴を確認する」](#在庫履歴を確認する)でログを確認 → [「棚卸しをする」](#棚卸しをする)で修正 |
| 商社を選択できない | [「商社を登録する」](#商社を登録する管理者のみ)で先に商社を登録する |
| パッケージが候補に出ない | [「パッケージ分類・パッケージ詳細」](#パッケージ分類パッケージ詳細)に追加する |
| 部品分類が候補に出ない | [「部品分類」](#部品分類)に追加する |
| スペック詳細が候補に出ない | [「スペック詳細」](#スペック詳細)に追加する。部品登録・詳細編集のスペック行からも管理者ならその場で追加できる |
| スペックの単位が出ない | [「スペック詳細」](#スペック詳細)で基準単位を登録する |
| 入力を間違えて保存してしまった | 部品詳細の「編集」で修正 → 管理者は[「操作ログ」](#操作ログ)で変更履歴を確認できる |
| Notion 同期が失敗する | [「Notion 連携設定」](#notion-連携設定)でトークンと DB ID を再確認 |
| 発注リストが消えた | 発注画面は閉じても保持されるが、ブラウザ内の保存データを消すと消える |
| 画面の表示が崩れる | ブラウザをハードリロード（Ctrl+Shift+R）する |
| DB を以前の状態に戻したい | [「バックアップから書き戻す」](#バックアップから書き戻す管理者のみ)を参照 |
| 権限を上げてほしい | [「ロールを変更する」](#ロールを変更する管理者のみ)を管理者に依頼 |

## 環境構築

> サーバーの構築・保守を担当する方向けの情報です。

### 動作環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 22.04 |
| Web サーバー | Apache2 + PHP-FPM |
| PHP | 8.3 |
| Laravel | 12 |
| Vue | 3 |
| Tailwind CSS | 3 |
| PostgreSQL | 16 |

### 初期構築手順

```bash
git clone <repo> /web/documents/BitsKeep
cd /web/documents/BitsKeep/bits-keep

composer install --no-dev
npm ci && npm run build

cp .env.example .env
php artisan key:generate
# .env の DB_* / APP_URL / FILESYSTEM_DISK を設定

# ⚠ 実行前に接続先・件数・バックアップ・復元手段の4点を確認すること
php artisan migrate --force

php artisan storage:link
```

### コード変更後の反映

```bash
cd bits-keep
npm run build   # 必ずビルドしてからブラウザをリロード
```

### やってはいけない操作

| 操作 | 理由 |
|---|---|
| `composer run dev` の実行 | `public/hot` が生成されブラウザが Vite サーバーに接続しようとして CSS/JS が全滅 |
| `php artisan serve` の実行 | Apache と競合する |
| `.env` を SQLite に変えて `migrate --force` | 本番 DB が空になる（2026-04-12 事故の再現） |

### DB 変更前の必須チェック（4点）

1. 接続先確認（`.env` の `DB_HOST` / `DB_DATABASE` を目視）
2. 件数確認（`SELECT COUNT(*) FROM components` などで実データを確認）
3. バックアップ確認（ダウンロード済みのダンプがあるか）
4. 復元手段確認（`psql` で書き戻せる状態か）

### バックアップ（CLI）

```bash
# DB 取得
PGPASSWORD=postgres pg_dump -h 127.0.0.1 -p 5432 -U postgres bitskeep \
  | gzip > /tmp/bitskeep_$(date +%Y%m%d).sql.gz

# DB 書き戻し
zcat /tmp/bitskeep_YYYYMMDD.sql.gz \
  | PGPASSWORD=postgres psql -h 127.0.0.1 -p 5432 -U postgres bitskeep

# ファイル（画像・データシート）取得
tar -czf /tmp/bitskeep_files_$(date +%Y%m%d).tar.gz \
  /web/documents/BitsKeep/bits-keep/storage/app/public/

# ファイル復元
tar -xzf /tmp/bitskeep_files_YYYYMMDD.tar.gz -C /
```
