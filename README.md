## 概要

BitsKeep は個人事業・小規模法人向けの電子部品管理システムです。部品の登録・在庫追跡・発注・案件紐付けをブラウザ上で一元管理します。

**アクセス URL:** https://bits-keep.rwc.0t0.jp/

---

## 機能一覧

| 機能 | 説明 |
|---|---|
| 部品管理 | スペック・画像・データシート・仕入先を登録。フリーワード・部品分類・スペック範囲で検索 |
| 在庫管理 | 入庫・出庫・在庫履歴。棚卸しモードで実数と差分を管理 |
| 発注管理 | 在庫警告から発注リストを作成し、商社別 CSV で出力 |
| 案件管理 | 案件と使用部品の紐付け。Notion との双方向同期 |
| 保管棚管理 | 棚のグループ管理・廃止・復元 |
| 商社管理 | 仕入先・単価・リードタイム・送料無料閾値 |
| マスタ管理 | パッケージ分類・パッケージ詳細・部品分類・スペック詳細・スペック候補設定・共通スペック詳細・許容差スペック詳細・入力テンプレートの管理 |
| 部品比較 | 最大5部品の仕様・価格を横並び比較（差分ハイライト） |
| Altium 連携 | SchLib/PcbLib 登録・部品詳細からシンボル/フットプリント紐付け |
| 設計ツール | 抵抗網計算・エンジニアリング計算補助 |
| ユーザー管理 | 招待メール・ロール設定（管理者/編集者/閲覧者） |
| 操作ログ | 全 CRUD 操作の変更差分を記録・フィルタ閲覧 |
| CSV インポート | テンプレート形式で部品データを一括登録 |
| DB バックアップ | pg_dump ダウンロード・SQL ファイルによる書き戻し |

## はじめる前に

### ログインとアカウント

管理者から招待メールが届いたら、メール内のリンクからパスワードを設定してログインします。

### 権限（ロール）

ログイン後、ヘッダ右上に自分の権限バッジが表示されます。

| 表示 | ロール | できること |
|---|---|---|
| 管理（赤枠） | admin | すべての操作 |
| 編集 | editor | 部品・在庫・案件の登録・編集 |
| 閲覧 | viewer | 一覧・詳細の参照のみ |

権限を変更したい場合は管理者に連絡してください。

### 最初にやること

BitsKeep を使い始める前に、以下のマスタを登録してください。部品登録時にこれらが必要になります。

1. **部品分類を登録する** — 「マスタ管理 → 部品分類」で「抵抗」「コンデンサ」「FPGA」などを追加
2. **パッケージ分類とパッケージ詳細を登録する** — 「マスタ管理 → パッケージ分類」で「SMD」「THT」を追加し、その配下に「0402」「SOT-23」などを追加
3. **部品分類ごとのスペック詳細を登録する** — 「マスタ管理 → 部品分類」で入力候補の親を用意し、「マスタ管理 → スペック詳細」で「静電容量」「耐圧」などを追加。必要に応じて英語名・記号・alias・基準単位も設定
4. **商社を登録する** — 「商社管理」で仕入先を追加
5. **保管棚を登録する** — 「保管棚管理」で棚を追加

## ダッシュボード

ログイン後の起点となる画面です。

### 今日の確認事項

- **在庫警告件数** — 発注点を下回った部品の件数。クリックで在庫警告画面へ
- **最近アクセスした部品** — 直近で開いた部品へのショートカット

### グローバル検索

**Ctrl+K**（Mac は Cmd+K）でどのページからでも検索ランチャーを起動できます。型番・通称でインクリメンタル検索し、Enter で詳細ページへ移動します。

### 業務別メニュー

ダッシュボード下部に「在庫入力」「在庫警告」「案件管理」などのショートカットが並んでいます。よく使う操作は並び替えて保存できます（ヘッダ右上「ホーム設定」）。

## 部品管理

### 部品を登録する

「部品一覧」→ 右上「+ 新規登録」から登録画面を開きます。

#### 入力項目

| 項目 | 必須 | 説明 |
|---|---|---|
| 型番 | ✓ | メーカー型番。重複チェックあり |
| 名称 | | 通称・社内管理名 |
| メーカー | | 製造元名 |
| 入手可否 | | 量産中 / EOL / 在庫限り / 非推奨 |
| 部品分類 | | 複数選択可。事前登録が必要（[マスタ管理](#マスタ管理)） |
| パッケージ分類 | | 大分類を選ぶとパッケージが絞り込まれる |
| パッケージ | | 0402・SOT-23 など |
| 代表保管棚 | | この部品を通常置く棚（[保管棚管理](#保管棚管理)で事前登録が必要） |
| スペック | | 「+ スペック追加」でスペック詳細を選び、`typ / 範囲 / 最大 / 最小 / 3値` の5種から値のコンテキストを選択して入力。通常は部品分類の候補スペック詳細と入力テンプレートを使い、必要な場合だけ全スペック詳細検索へ切り替える。入力中に「基底: 1000Ω / 表示: 1kΩ」のようなリアルタイムプレビューが表示される。候補にないスペック詳細は部品分類が一意に決まる場合だけ行内の「+」から追加可能 |
| 仕入先 | | 商社・商社型番・単価・購入単位・価格ブレーク。複数追加可 |
| 部品画像 | | jpg/png/webp、5MB まで |
| データシート | | PDF ファイル。複数添付可。各PDFに表示名を付けられる |
| カスタムフィールド | | 任意のキーと値を自由に追加 |

#### スペック詳細の選択

部品登録と部品詳細のスペック編集では、部品分類に応じて `部品分類からの推奨` が先に表示されます。通常表示は選択中の部品分類に紐づく候補スペック詳細だけを出し、候補外が必要な場合は `全スペック詳細から選ぶ` に明示的に切り替えて検索します。

部品分類に紐づく入力テンプレートがある場合は、スペック欄にテンプレートボタンが表示されます。適用するとテンプレート内のスペック行を追加し、既に同じスペック詳細がある行は重複追加しません。

部品分類チップは選択中の部品分類だけを表示します。未選択の部品分類は候補チップに混ぜず、複合部品などで候補外を探す場合は全スペック詳細検索へ退避します。全スペック詳細検索中でも、選択中部品分類の候補スペック詳細は `推奨` と分かるように表示されます。

#### 保存

フォーム上部と下部に「保存」ボタンがあります。長いフォームを下まで入力した後、画面を上に戻らなくても保存できます。

#### データシート解析補助

現状の部品登録では、データシートからの補助入力に次の 3 系統があります。

- `ChatGPTで自動入力` — Tampermonkey userscript 経由で `PDF選択 -> 一時アップロード -> ChatGPT Web 解析 -> レビュー` まで自動化
- `ChatGPTから貼り付け` — ChatGPT で PDF を読ませた結果 JSON を貼り付けてレビューする
- `Geminiで解析` — API 利用を許容する環境だけの任意導線

解析レビューでは部品分類候補を既存部品分類へ紐付けると、その部品分類に対応する候補スペック詳細と入力テンプレート候補が表示されます。テンプレートを選ぶとレビュー中のスペック候補へ行を追加し、内容を確認してからフォームへ適用できます。

どちらの導線でも、解析後はいったんレビュー用モーダルが開きます。ここで次を確認・修正してからフォームへ適用します。

- 基本情報: `型番` `メーカー` `通称` `説明`
- 部品分類候補: `component_types[]` からデコードした複数候補を既存部品分類へ紐付けて選択
- パッケージ候補: `package_names[]` からデコードした複数候補の中から、既存の `パッケージ分類 / パッケージ詳細` へ紐付けた 1 件を選択
- スペック候補: `name / name_ja / name_en / symbol` を使って既存スペック詳細へ照合し、未一致項目はレビュー画面の「+」から追加、削除

データシート上の元表記は `抽出名` として確認用に表示されますが、保存される正本は `spec_type_id` です。表記ゆれはスペック詳細の alias に寄せて管理します。

`ChatGPTで自動入力` は `Tampermonkey` userscript を前提に、`PDF選択 -> BitsKeepへ一時アップロード -> ChatGPT Web 解析 -> 結果レビュー -> 保存` を自動化します。自動化に失敗した場合は、同じ画面から `ChatGPTから貼り付け` へ即切り替えられます。応答テキストのコピー補助もあるため、DOM 変更やログイン切れが起きても手動 fallback へ退避できます。

Tampermonkey helper が未接続でも、部品登録画面を開いただけでは案内モーダルを自動表示しません。`ChatGPTで自動入力` などの解析操作を押した時だけ、導入・更新・手動貼り付けへの切替案内を表示します。

#### Tampermonkey 導入手順

1. `https://bits-keep.rwc.0t0.jp/tampermonkey/bitskeep-chatgpt-helper.user.js` を Tampermonkey へインストールする
2. `https://bits-keep.rwc.0t0.jp/*` と `https://chatgpt.com/*` への実行を許可する
3. ChatGPT にログインした状態で BitsKeep の部品登録画面を再読込する
4. PDF を選択して `ChatGPTで自動入力` を押す
5. 自動化が失敗したら案内モーダルから `ChatGPTから貼り付け` へ切り替える

#### userscript 更新手順

1. 部品登録画面の `ChatGPT自動解析` モーダルから `userscript を更新` を押す
2. Tampermonkey の更新確認画面で `再インストール` または `更新` を承認する
3. `再読込して反映` を押して部品登録画面へ更新版 userscript を反映する
4. 再読込後に helper 成功トーストが出れば更新完了。旧版のままなら更新ダイアログが再表示される

`userscript を更新` 導線はキャッシュ回避クエリ付き URL を開きます。さらに userscript 自体にも `@downloadURL` / `@updateURL` を埋め込み、Tampermonkey 側の更新元を固定しています。

#### 一時PDFの扱い

- ChatGPT 自動入力で選択した PDF は一時保存され、署名付き URL で ChatGPT タブへ渡されます
- 一時PDFの有効期限は 2 時間です
- 部品保存が成功すると一時PDFは正式なデータシートへ確定され、使い終わった token は再利用できません
- キャンセル時は BitsKeep 側から一時PDF破棄 API を呼んで消します

### 既存部品を複製して登録する

同じメーカーの別型番など、似た部品を素早く登録できます。

1. 複製元の部品詳細ページを開く
2. 「複製」ボタンをクリック
3. 型番など差分だけ修正して「保存」

### 部品を探す

#### 基本検索

部品一覧の上部にある検索バーで型番・名称・メーカーをキーワード検索できます。

#### 詳細フィルタ

「詳細条件」を開くと以下の条件で絞り込めます。

- 部品分類（複数選択可）
- 入手可否
- メーカー
- パッケージ分類 / パッケージ
- スペック詳細 + 値の範囲（例: 静電容量 100nF〜10μF）
- 在庫状態（在庫あり / 在庫切れ / 警告中）
- 購入日の範囲

フィルタを適用した状態は「フィルタチップ」として表示され、1クリックで個別に解除できます。

#### お気に入り

部品カードの星アイコンでお気に入り登録できます。「お気に入りのみ」フィルタで一覧を絞り込めます。

#### 並び順

既定は部品分類、パッケージ分類、パッケージ、型番の順に並ぶ台帳向け表示です。型番内の数字は自然順で扱うため、`2SC945` は `2SC1815` より前に並びます。必要に応じて更新順、通称順、型番順へ切り替えできます。

### 部品を比較する

1. 部品一覧でカード左上のチェックボックスを選択（最大5件）
2. 画面下部に表示される「比較」ボタンをクリック
3. 比較画面でスペック・価格・在庫を横並びで確認

差分がある行はハイライト表示されます。「差異のある行のみ表示」チェックで絞り込めます。

### 部品詳細

部品詳細ページでは以下の情報を確認・操作できます。

- 基本情報・スペック・仕入先・画像・データシート
- 在庫数（新品 / 中古 別）と保管棚
- **入庫 / 出庫** ボタン（[在庫管理](#在庫管理)）
- 在庫履歴（入出庫のログ）
- 関連案件（この部品を使っている案件一覧）
- 類似部品（同じ部品分類・パッケージの部品候補）
- Altium リンク（シンボル名・フットプリント名）

## 在庫管理

### 入庫する

#### 部品詳細から入庫

1. 部品詳細ページ → 右上「入庫」
2. 以下を入力して「確定」

| 項目 | 説明 |
|---|---|
| 数量 | 入庫する個数 |
| 区分 | 新品 / 中古 |
| 保管棚 | 置く棚（複数棚への分配も可） |
| ロット番号 | 任意 |
| 備考 | 任意 |

#### 在庫入力画面からまとめて入庫

複数部品をまとめて入庫する場合はこちらが便利です。

1. ダッシュボード「在庫入力」または全機能一覧 →「在庫入力」
2. 部品を検索して追加
3. 各部品の数量・棚を入力
4. 「一括登録」で確定

### 出庫する

1. 部品詳細ページ →「出庫」
2. 数量・用途・備考を入力して「確定」

在庫が足りない場合はエラーが表示されます。

### 在庫履歴を確認する

部品詳細ページ下部の「在庫履歴」セクションに入出庫のすべてのログが表示されます。日時・操作者・数量・棚・備考を確認できます。

### 在庫警告

発注点（`min_stock`）を下回った部品は自動的に在庫警告として検出されます。

- ダッシュボードの警告バッジで件数を確認できます
- 全機能一覧 →「在庫警告」で一覧を確認できます

発注点は部品登録・編集画面の「在庫下限」フィールドで設定します。

### 棚卸しをする

実際の在庫数とシステムの在庫数を照合・修正します。

1. 「保管棚」→ 右上「棚卸しモード」をオン
2. 画面上部のオレンジのバーが表示されます（棚卸し中の目印）
3. 各棚の「実数」欄に実際の在庫数を入力（現在の在庫数がデフォルト表示）
4. 差分（±）がリアルタイムで表示されます
5. 「確定」で保存 — 差分が在庫に反映されます

棚卸しモード中は「棚卸しモード終了」ボタンで確定せずに終了できます。

## 発注管理

### 在庫警告を確認する

全機能一覧 →「在庫警告」で発注点を下回った部品の一覧を表示します。

各行には以下の情報が表示されます。
- 型番・通称
- 現在の在庫数（新品 / 中古）
- 発注点との差分
- 発注済みで納品待ちの件数

### 発注リストを作る

1. 在庫警告画面で発注したい部品にチェックを入れる
2. 「発注リストへ追加」ボタンをクリック
3. 発注画面（全機能一覧 →「発注画面」）に部品が追加される

### 発注画面で内容を決める

発注画面では各部品について以下を設定します。

| 項目 | 説明 |
|---|---|
| 購入単位 | バラ / テープ / トレー / リール / 箱 |
| 購入数量 | 発注する個数 |
| 購入商社 | 仕入先を選択。選択すると商社型番と単価が自動入力される |

### 商社別 CSV を出力する

「〇〇商社 をCSV出力」ボタンで、その商社向けの発注シートを CSV で書き出します。

CSV の列: 型番 / 通称 / パッケージ / 購入単位 / 商社 / 商社型番 / 数量 / 単価 / 小計

## 案件管理

### 案件を作成する

1. 全機能一覧 →「案件管理」→「+ 案件を追加」
2. 案件名・事業（Notion 事業 DB と紐付く）を入力して保存

### 使用部品を追加する

案件詳細ページの「使用部品」セクションで部品を検索して追加します。使用数も合わせて記録できます。

### Notion 同期

「連携設定」で Notion API トークンと事業データベース ID を設定すると、Notion 上の案件データを BitsKeep に同期できます。

- 同期は「案件管理」画面の「同期」ボタンで手動実行します
- 同期結果（成功 / 失敗 / 件数）が画面上に表示されます
- Notion で作成した案件は `origin: Notion` として取り込まれます

Notion 連携の設定方法は [Notion 連携設定](#notion-連携設定) を参照してください。

## 保管棚管理

### 棚を登録する（管理者のみ）

1. 「保管棚」→「+ 棚を追加」
2. 以下を入力して保存

| 項目 | 説明 |
|---|---|
| 棚コード | 識別コード（例: A-01） |
| 棚名称 | 表示名 |
| グループ | 棚のグループ名（例: メインラック、引き出し） |
| 並び順 | 一覧での表示順 |
| 備考 | 任意 |

### 棚を廃止する

使わなくなった棚は「廃止」にすると選択候補から消えます。在庫データへの影響はありません。管理者は「復元」でいつでも元に戻せます。

## 商社管理

### 商社を登録する（管理者のみ）

「商社管理」→「+ 新規追加」から登録します。

| 項目 | 説明 |
|---|---|
| 商社名 | 必須 |
| URL | 商社の Web サイト |
| リードタイム | 発注から納品までの日数（目安） |

## マスタ管理

部品登録に必要な部品分類・パッケージ詳細・スペック詳細・候補設定・入力テンプレートを管理します。

マスタ管理のタブは URL の `tab` クエリで保持されます。例: `/master?tab=packages`、`/master?tab=spec-types`。タブ移動後にリロードしても同じタブで開き、ブラウザの戻る/進むでもタブ状態が追従します。スペック系は `部品分類`、`スペック詳細`、`スペック候補設定`、`共通スペック詳細`、`許容差スペック詳細`、`入力テンプレート` に責務を分け、入力テンプレートは一番右に置きます。

### 部品分類

「抵抗」「コンデンサ」「FPGA」など部品の種類を表すタグです。部品には複数の部品分類を付けられます。部品分類はスペック詳細の候補と入力テンプレートの親でもあります。

- 一覧はドラッグ&ドロップで表示順を変更できます
- 使わなくなった部品分類は「アーカイブ」で候補から外せます（部品への紐付けは残ります）

### 部品分類と候補スペック詳細

`部品分類` は部品そのものに付ける種類・検索タグであり、スペック詳細の候補・並び順・既定値を束ねる入力候補グループでもあります。

例: 部品分類が `BJT` のとき、その中に `VCEO`、`コレクタ電流`、`hFE`、`fT` などの候補スペック詳細を並べます。DB/API内部名は `spec_groups` / `/api/spec-groups` に統一します。旧 `/api/categories` は使いません。

### 部品シリーズ（今後の設計方針）

抵抗・コンデンサ・インダクタなど、同一シリーズの中に値違いが大量にある部品は、単体部品を1件ずつ並べるのではなく、`部品シリーズ` と値マトリクスで扱う方針です。一方で IC・MCU・センサ・モジュールなど、型番ごとの差分が大きい部品は従来通り単体部品として管理します。

値展開方式は E系列だけに固定しません。シリーズごとに次の方式を選べるようにします。

- `E系列`: E12 / E24 / E96 などの標準系列から値を生成する
- `基準系列 + 追加値`: E12 を基準にしつつ、一部だけ E24 の値を追加するような混在を正式に扱う
- `任意値リスト`: ツェナー電圧、水晶周波数、ヒューズ電流、コネクタ極数など、E系列に乗らない値を手入力・CSV貼り付けで持つ
- `範囲/刻み`: ピン数や定格電流のように、一定範囲を刻みで展開する

値マトリクス上の値は、在庫や仕入先を持たない `仮想値` と、実際に登録・在庫管理する `実部品` を分けます。シリーズ全体の候補値は広く持ちつつ、実際に使う値だけを部品化して在庫・価格・保管棚を管理することで、E12中心に少量のE24が混ざる運用や、E系列外のツェナー・水晶でも破綻しにくくします。

### パッケージ分類・パッケージ詳細

パッケージは2階層で管理します。

- **パッケージ分類**（例: SMD、THT）— 大分類
- **パッケージ詳細**（例: 0402、0603、SOT-23）— パッケージ分類に属する個別形状

部品登録時はパッケージ分類を選んでからパッケージを選びます。

### スペック詳細

「静電容量」「耐圧」「周波数」など、検索・比較したい仕様項目を定義します。スペック詳細には **日本語名 / 英語名 / 記号 / alias / 基準単位** を設定できます。

- 日本語名は画面表示と標準検索名に使います
- 英語名・記号・alias は、英語データシートや略記号から同じスペック詳細へ照合するために使います
- 同じ日本語名のスペック詳細を複数登録できます。例: `電源電圧` を `VDD` と `VCC` で別々に持つ場合は、記号・alias で区別します
- `スペック詳細` タブでは先に部品分類を選び、その部品分類を主所属に持つ通常スペック詳細だけを表示・追加・編集・アーカイブします。スペック詳細の全件一覧や全件並び替えは行いません
- 主所属を持つスペック詳細は選択中の部品分類の候補として追加・編集・アーカイブします。内部では `spec_types.spec_scope='group_local'` と `owner_spec_group_id` で主所属の部品分類を持ちます。これは専用ではなく主所属であり、再利用できます
- 共通スペック詳細は「共通スペック詳細」タブで左の部品分類を選び、追加・編集・アーカイブと、選択中の部品分類への `候補に入れる` / `候補から外す` を扱います
- スペック候補設定タブの行 `編集` は、候補側の種別表示・扱い・既定profile・既定単位・メモだけを編集します。名称・記号・alias・単位等の正本編集は、各スペック詳細タブの `編集` で行います
- スペック候補設定タブで候補へ追加するときは、`スペック詳細から追加`、`共通スペック詳細から追加`、`許容差スペック詳細から追加` の3系統から既存項目を選びます。このタブではスペック詳細の新規作成やフリー入力を開きません
- スペック候補設定タブの候補順はドラッグ&ドロップで変更します。上下ボタンでの並び替えは使いません
- 許容差スペック詳細は、通常の共通スペック詳細とは兄弟の別棚として管理します。UIでは左の部品分類を選んで候補状態を見ながら、`共通スペック詳細` と `許容差スペック詳細` を別一覧・別追加ボタンに分けます。通常/許容差を切り替えるラジオや、許容差タブ内の行別 `許容差` バッジは置きません
- DB/API正本は引き続き `spec_types` です。内部種別は `spec_kind=normal/tolerance` で区別し、許容差スペック詳細は `tolerance_settings` に `default_mode`、`default_unit`、`allowed_units`、`grade_options` などを持てます
- 許容差スペック詳細の例: `抵抗値許容差 ±5%`、`容量許容差 B級 ±0.1pF`、`容量許容差 Z級 +80/-20%`、`抵抗温度係数 ±100ppm/℃`、`容量温度特性 X7R`
- 記号は HTML ではなく `h_FE` `V_CBO` `V_CE-(sat)` のように保存します。`_` は下付き、`~` は上付き、`-` は通常表示へ戻す区切りです
- 基準単位は 1 つだけ設定します（例: 静電容量 → F、電流 → A）

### 入力テンプレート

入力テンプレートは、部品分類ごとにスペック行をまとめて追加する初期行セットです。候補スペック詳細の所属・並び順・既定値は `スペック候補設定` タブ、入力テンプレートは `入力テンプレート` タブで編集します。テンプレート行で選べるスペック詳細は、関連する部品分類の候補スペック詳細だけに絞ります。`共通` は部品分類として表示・選択せず、共通スペック詳細として管理します。

マスタ正本の廃止は `アーカイブ`、候補関係の解除は `候補から外す` と表示します。`候補から外す` は正本削除ではありません。

部品登録時の表示単位は、基準単位から自動で人間向けに読みやすい接頭語へ寄せます。例:

- `0.000001 A` は `1uA`
- `1000 Ω` は `1kΩ`
- `0.000000005 s` は `5ns`

登録画面ではスペック行に自由な「名前」欄はありません。必ずスペック詳細を選び、候補にない場合だけその場の追加モーダルでスペック詳細を登録します。値は `typ / 範囲 / 最大 / 最小 / 3値` の5種を扱えます。内部検索は常に基準単位へ正規化して行うため、`1uA` と `1e-6A` は同じ値として扱われます。

UI表示名は `部品分類` / `パッケージ詳細` / `スペック詳細` / `スペック候補設定` / `候補スペック詳細` / `入力テンプレート` / `共通スペック詳細` / `許容差スペック詳細` に整理しています。DB/API/コード内部名は `spec_groups` / `packages` / `spec_types` / `spec_group_spec_type` / `spec_templates` / `/api/spec-groups` / `/api/packages` / `/api/spec-types` / `/api/spec-templates` を正とします。旧 `categories` テーブルは移行元であり、旧 `/api/categories` は廃止します。対応表は仕様書を正とします。

## 困ったときは

| 困りごと | 参照先 |

### 初期構築手順

```bash
git clone <repo> /web/documents/BitsKeep
cd /web/documents/BitsKeep/bits-keep

composer install --no-dev
npm ci && npm run build

cp .env.example .env
php artisan key:generate
# .env の DB_* / APP_URL / FILESYSTEM_DISK を設定

# ⚠ 実行前に接続先・件数・バックアップ・復元手段の4点を確認すること

```

### コード変更後の反映

```bash
cd bits-keep
npm run build   # 必ずビルドしてからブラウザをリロード
```

### やってはいけない操作

| 操作 | 理由 |
|---|---|
| `composer run dev` の実行 | `public/hot` が生成されブラウザが Vite サーバーに接続しようとして CSS/JS が全滅 |
| `php artisan serve` の実行 | Apache と競合する |
| `.env` を SQLite に変えて `migrate --force` | 本番 DB が空になる（2026-04-12 事故の再現） |

### DB 変更前の必須チェック（4点）

1. 接続先確認（`.env` の `DB_HOST` / `DB_DATABASE` を目視）
2. 件数確認（`SELECT COUNT(*) FROM components` などで実データを確認）
3. バックアップ確認（ダウンロード済みのダンプがあるか）
4. 復元手段確認（`psql` で書き戻せる状態か）

### バックアップ（CLI）

```bash
# DB 取得
PGPASSWORD=postgres pg_dump -h 127.0.0.1 -p 5432 -U postgres bitskeep \
  | gzip > /tmp/bitskeep_$(date +%Y%m%d).sql.gz

# DB 書き戻し
zcat /tmp/bitskeep_YYYYMMDD.sql.gz \
  | PGPASSWORD=postgres psql -h 127.0.0.1 -p 5432 -U postgres bitskeep

# ファイル（画像・データシート）取得
tar -czf /tmp/bitskeep_files_$(date +%Y%m%d).tar.gz \
  /web/documents/BitsKeep/bits-keep/storage/app/public/

# ファイル復元
tar -xzf /tmp/bitskeep_files_YYYYMMDD.tar.gz -C /
```
