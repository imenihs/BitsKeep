## 概要

BitsKeep は個人事業・小規模法人向けの電子部品管理システムです。部品の登録・在庫追跡・発注・案件紐付けをブラウザ上で一元管理します。

**アクセス URL:** https://bits-keep.rwc.0t0.jp/

画像付きの操作手順は、ログイン後のヘッダ「使い方」または `/help` のアプリ内ガイドを参照してください。実画面の全体スナップショットと操作箇所の拡大画像で、部品一覧、部品登録、在庫、マスタ管理、設計ツール、バックアップの導線を確認できます。

ガイド画像を更新する場合は、公開してよいデモ/検証データの環境で `BITSKEEP_URL`、`BITSKEEP_GUIDE_EMAIL`、`BITSKEEP_GUIDE_PASSWORD` を設定し、`bits-keep/` で `npm run capture:guide` を実行します。共有環境の実データを撮る場合は `BITSKEEP_GUIDE_ALLOW_REAL_DATA=1` を明示し、撮影後に個人情報や業務上公開できない情報が写っていないことを確認してください。画像実体は `resources/help/screenshots/` に保存し、認証付きの `/help-guide/screenshots/{filename}` から配信します。

## はじめる前に

### ログインとアカウント

管理者から招待メールが届いたら、メール内のリンクからパスワードを設定してログインします。

### 権限

ログイン後、ヘッダ右上に自分の権限バッジが表示されます。

| 表示 | できること |
|---|---|
| 管理（赤枠） | すべての操作 |
| 編集 | 部品・在庫・案件の登録・編集 |
| 閲覧 | 一覧・詳細の参照のみ |

権限を変更したい場合は管理者に連絡してください。

### 最初にやること

BitsKeep を使い始める前に、以下のマスタを登録してください。部品登録時にこれらが必要になります。

1. **部品分類を登録する** — 「マスタ管理 → 部品分類」で「抵抗」「コンデンサ」「FPGA」などを追加
2. **パッケージ分類とパッケージ詳細を登録する** — 「マスタ管理 → パッケージ分類」で「SMD」「THT」を追加し、その配下に「0402」「SOT-23」などを追加
3. **部品分類ごとのスペック詳細を登録する** — 「マスタ管理 → 部品分類」で入力候補の親を用意し、「マスタ管理 → スペック詳細」で「静電容量」「耐圧」などを追加。必要に応じて英語名・記号・別名・標準単位も設定
4. **商社を登録する** — 「商社管理」で仕入先を追加
5. **保管棚を登録する** — 「保管棚管理」で棚を追加

## ダッシュボード

ログイン後の起点となる画面です。

### 今日の確認事項

- **在庫警告件数** — 発注点を下回った部品の件数。クリックで在庫警告画面へ

**Ctrl+K**（Mac は Cmd+K）でどのページからでも検索ランチャーを起動できます。型番・通称でインクリメンタル検索し、Enter で詳細ページへ移動します。

### 業務別メニュー

ダッシュボード下部に「在庫入力」「在庫警告」「案件管理」などのショートカットが並んでいます。よく使う操作は並び替えて保存できます（ヘッダ右上「ホーム設定」）。

## 部品管理

### 部品を登録する

「部品一覧」→ 右上「+ 新規登録」から登録画面を開きます。

#### 入力項目

| 項目 | 必須 | 説明 |
|---|---|---|
| 型番 | ✓ | メーカー型番。重複チェックあり |
| 名称 | | 通称・社内管理名 |
| メーカー | | 製造元名 |
| 入手可否 | | 量産中 / EOL / 在庫限り / 非推奨 |
| 部品分類 | | 複数選択可。事前登録が必要（[マスタ管理](#マスタ管理)） |
| パッケージ分類 | | 大分類を選ぶとパッケージが絞り込まれる |
| パッケージ | | 0402・SOT-23 など |
| 代表保管棚 | | この部品を通常置く棚（[保管棚管理](#保管棚管理)で事前登録が必要） |
| 登録単位 | | `単体` / `シリーズ`。シリーズを選ぶ場合は `部品シリーズ` と `シリーズ値` を選び、登録部品をシリーズ値へ紐づける |
| スペック | | `部品分類` で候補を絞り、`スペック候補` で1行追加、`入力テンプレート` の `一式追加` で複数行を追加する。値種別は `TYP`、`MIN..MAX`、`MAX`、`MIN`、`MIN/TYP/MAX` から選ぶ。入力中は `入力値` と `標準単位換算` を確認できる。候補にないスペック詳細は、スペック追加カード下段の `スペックを新規で追加` から追加可能 |
| 仕入先 | | 商社・商社型番・単価・購入単位・価格ブレーク。複数追加可 |
| 部品画像 | | jpg/png/webp、5MB まで |
| データシート | | PDF ファイル。複数添付可。各PDFに表示名を付けられる |
| カスタムフィールド | | 任意のキーと値を自由に追加 |

#### スペック詳細の選択

部品登録と部品詳細のスペック編集は、説明カードではなく構造で操作対象が分かるUIにします。

1. `部品分類` select で、マスタ上の部品分類または `フィルタしない` を選びます。部品詳細のスペック編集では、現在の部品分類を初期選択します。
2. `スペック候補` dropdown は選択中の部品分類で絞り込まれ、`追加` で1行を登録済みスペックへ追加します。
3. `入力テンプレート` dropdown は選択中の部品分類に紐づくテンプレートだけを出し、`一式追加` でテンプレート内の行をまとめて追加します。
4. テンプレート選択時は `[ピーク耐圧 V_RRM]` のように、実際に一括追加されるスペック詳細の日本語名と略号をチップでプレビューします。単なる「x項目」表示だけにはしません。
5. 追加済みの行は下部の `登録済みスペック` に並べ、値・単位・入力形式を編集します。既に同じスペック詳細がある行は重複追加しません。

部品詳細のスペック編集からは、選択中の部品分類を引き継いで `スペック詳細`、`スペック候補設定`、`共通スペック詳細`、`許容差スペック詳細`、`入力テンプレート` の各マスタへ移動できます。候補にない個別スペック詳細は、スペック追加カード下段の `スペックを新規で追加` から追加します。同名の既存スペック詳細がある場合は新規作成せず、選択中部品分類の候補へ追加してから登録済みスペック行へ追加します。新規追加モーダルの `基準単位` は `F` / `Ω` / `A` のような基底単位だけを入力し、`u` / `k` などは値入力で使える `入力候補接頭辞` として選びます。共通・許容差・テンプレートの設計変更はマスタ管理側で行います。

#### 保存

フォーム上部と下部に「保存」ボタンがあります。長いフォームを下まで入力した後、画面を上に戻らなくても保存できます。

#### データシート解析補助

部品登録画面の主導線は `データシートから自動入力` の 1 本です。PDF を選んでこのボタンを押すと、解析結果のレビュー画面まで進みます。

どこで解析するかは `連携設定 > 解析の実行方式` で決める運用設定であり、利用者が解析ごとに選ぶ必要はありません。ボタン名にも解析エンジン名は出しません。

- `データシートから自動入力` — 主導線。サーバ側で解析し、完了したらレビュー画面を開く
- `解析結果を貼り付け` — 解析結果 JSON を貼り付けてレビューする退避導線

主導線の解析はサーバ側で動くため、**部品登録画面を閉じてもブラウザを再読込しても解析は続きます**。画面へ戻ると進行中の解析の続きを表示します。解析中は進行状態と `中止する` だけを出し、待つ以外の判断を利用者へ求めません。

解析が失敗したときは、失敗理由に応じて次の一手だけを出します。

| 失敗の種類 | 画面に出る導線 |
|---|---|
| ログイン切れ・実行環境の不備 | `連携設定を開く` |
| 制限時間超過・利用枠の上限到達 | `もう一度実行` |
| 文字もページ画像も取り出せないPDF・想定外の形式 | `貼り付けで入力` |

旧方式（`ChatGPTタブで解析` / `この画面で待つ解析`）は `別の解析方法を使う（旧方式）` の中に残しています。どちらも画面またはブラウザのタブを開いたままにする必要があるため、既定の導線からは外しています。

解析レビューでは部品分類候補を既存部品分類へ紐付けると、その部品分類に対応する候補スペック詳細と入力テンプレート候補が表示されます。テンプレートを選ぶとレビュー中のスペック候補へ行を追加し、内容を確認してからフォームへ適用できます。

どの導線でも、解析後はいったんレビュー用モーダルが開きます。ここで次を確認・修正してからフォームへ適用します。

- 基本情報: `型番` `メーカー` `通称` `説明`
- 部品分類候補: 解析結果の複数候補から、既存の部品分類へ紐付けて選択
- パッケージ候補: 解析結果の複数候補から、既存の `パッケージ分類 / パッケージ詳細` へ紐付けた 1 件を選択
- スペック候補: 日本語名・英語名・記号・別名を使って既存スペック詳細へ照合し、未一致項目はレビュー画面の「+」から追加、削除

データシート上の元表記は `データシート表記` として確認用に表示され、保存時は既存のスペック詳細へ紐付けます。表記ゆれはスペック詳細の別名として管理します。

`ChatGPTで自動入力` は `Tampermonkey` userscript を前提に、`PDF選択 -> BitsKeepへ一時アップロード -> ChatGPT Web 解析 -> 結果レビュー -> 保存` を自動化します。自動化に失敗した場合は、同じ画面から `ChatGPTから貼り付け` へ即切り替えられます。応答テキストのコピー補助もあるため、ChatGPT画面の変更やログイン切れが起きても手動貼り付けへ切り替えられます。

Tampermonkey連携が未接続でも、部品登録画面を開いただけでは案内モーダルを自動表示しません。`ChatGPTで自動入力` などの解析操作を押した時だけ、導入・更新・手動貼り付けへの切替案内を表示します。

#### サーバ内解析のセットアップ（管理者向け）

主導線の `データシートから自動入力` をサーバ内解析で動かすには、サーバ側で次の準備が必要です。準備が済んでいない場合、`連携設定 > 解析の実行方式` に不足内容がそのまま表示されます。

1. **PDF 変換ツールを入れる**
   PDF はそのまま解析エンジンへ渡せないため、文字またはページ画像へ変換します。
   ```bash
   sudo apt install poppler-utils
   ```
2. **Codex CLI を入れる**
   ```bash
   sudo npm install -g @openai/codex
   ```
3. **解析専用の設定ディレクトリを作る**
   認証情報は自動更新されるため、キューワーカーの実行ユーザから書き込めるディレクトリが必要です。Web サーバ実行ユーザのホームは使いません。
   ```bash
   sudo mkdir -p /var/lib/bitskeep-codex
   sudo chown www-data:www-data /var/lib/bitskeep-codex
   sudo chmod 700 /var/lib/bitskeep-codex
   ```
4. **サーバ上でログインする**
   ログインはブラウザでの承認が必要です。サーバにブラウザがない場合は、手元の PC から SSH ポートフォワードを張り、手元のブラウザで承認します。

   まず手元の PC で、サーバの承認用ポートを転送します（接続したままにします）。
   ```bash
   ssh -p <SSHポート> -L 1455:localhost:1455 <ユーザー>@<サーバー>
   ```
   次にサーバ側でログインを開始します。表示された URL を手元のブラウザで開いて承認します。
   ```bash
   sudo -u www-data env CODEX_HOME=/var/lib/bitskeep-codex HOME=/var/lib/bitskeep-codex codex login
   ```
   `/var/lib/bitskeep-codex/auth.json` ができれば成功です。

   > Codex CLI は「ヘッドレス環境では `--device-auth` を使う」と案内することがありますが、この指定は版によっては用意されていません。使えない場合は上記のポートフォワード方式で承認します。

5. **サンドボックス用ディレクトリの権限を固定する**
   Codex は解析時、`/tmp/codex-bwrap-synthetic-mount-targets/` という**実行ユーザ共通の固定パス**へロックを作ります。ここが別のユーザ所有で作られているとキューワーカーから書き込めず、**解析は成功扱いのまま結果だけ空になります**。`/tmp` は再起動で消えるため、次の定義を置いて権限を固定します。
   ```bash
   echo 'd /tmp/codex-bwrap-synthetic-mount-targets 1777 root root -' \
     | sudo tee /etc/tmpfiles.d/bitskeep-codex.conf
   sudo systemd-tmpfiles --create /etc/tmpfiles.d/bitskeep-codex.conf
   ```

6. **キューワーカーを常駐させる**
   解析はキュー経由で実行するため、ワーカーが動いていないと解析が `順番待ち` のまま進みません。systemd などで常駐させます。実行ユーザは、手順 3 のディレクトリへ書き込める `www-data` に合わせます。
   ```bash
   php artisan queue:work --queue=default --tries=1
   ```
7. **連携設定で確認する**
   `連携設定 > 解析の実行方式` を開き、`サーバ内解析` が `利用可能` になっていることを確認します。

環境変数で上書きできる主な設定は次のとおりです。既定値のままでも動きます。

| 変数 | 既定値 | 用途 |
|---|---|---|
| `DATASHEET_ENGINE` | `codex` | 連携設定が未保存のときの解析方式 |
| `DATASHEET_ANALYSIS_TIMEOUT` | `300` | 解析1件に許す秒数 |
| `CODEX_BINARY` | `/usr/local/bin/codex` | Codex CLI の実行ファイル |
| `CODEX_HOME` | `/var/lib/bitskeep-codex` | Codex の設定と認証情報の置き場所 |
| `CODEX_MODEL` | 未指定 | 解析に使うモデル。未指定なら Codex 側の既定 |
| `CODEX_WORKSPACE_ROOT` | OS の一時ディレクトリ配下 | 解析ごとの作業ディレクトリの親。**アプリ配下は指定不可** |
| `PDFTOTEXT_BINARY` | `/usr/bin/pdftotext` | PDF から文字を取り出すコマンド |
| `PDFTOPPM_BINARY` | `/usr/bin/pdftoppm` | PDF をページ画像へ変換するコマンド |
| `DATASHEET_PDF_TEXT_THRESHOLD` | `800` | この文字数を下回るPDFはスキャン原稿と判断してページ画像へ切り替える |
| `DATASHEET_PDF_MAX_IMAGE_PAGES` | `12` | ページ画像として渡す最大ページ数 |

作業ディレクトリをアプリ配下へ向けると `AGENTS.md` や `CLAUDE.md` が読み込まれて解析指示が汚染されるため、アプリ配下が指定されている場合は解析を実行せずエラーにします。

#### Tampermonkey 導入手順

1. `https://bits-keep.rwc.0t0.jp/tampermonkey/bitskeep-chatgpt-helper.user.js` を Tampermonkey へインストールする
2. `https://bits-keep.rwc.0t0.jp/*` と `https://chatgpt.com/*` への実行を許可する
3. ChatGPT にログインした状態で BitsKeep の部品登録画面を再読込する
4. PDF を選択して `ChatGPTで自動入力` を押す
5. 自動化が失敗したら案内モーダルから `ChatGPTから貼り付け` へ切り替える

#### userscript 更新手順

1. 部品登録画面の `ChatGPT自動解析` モーダルから `userscript を更新` を押す
2. Tampermonkey の更新確認画面で `再インストール` または `更新` を承認する
3. `再読込して反映` を押して部品登録画面へ更新版 userscript を反映する
4. 再読込後に連携成功トーストが出れば更新完了。旧版のままなら更新ダイアログが再表示される

`userscript を更新` 導線はキャッシュ回避クエリ付き URL を開きます。さらに userscript 自体にも `@downloadURL` / `@updateURL` を埋め込み、Tampermonkey 側の更新元を固定しています。

#### 一時PDFの扱い

- 解析対象に選んだ PDF はサーバへ一時保存されます。旧方式の ChatGPT タブへは署名付き URL で渡されます
- 一時PDFの有効期限は 2 時間です
- サーバ内解析では、PDF から取り出した文字やページ画像は解析ごとの作業ディレクトリへ置き、解析の成否によらず終了時に削除します
- 部品保存が成功すると一時PDFは正式なデータシートへ確定され、使い終わった一時リンクは再利用できません
- キャンセル時は BitsKeep 側で一時PDFを破棄します

## マスタ管理

部品登録に必要な部品分類・パッケージ詳細・スペック詳細・候補設定・入力テンプレートを管理します。

マスタ管理のタブは URL の `tab` クエリで保持されます。例: `/master?tab=packages`、`/master?tab=spec-types`。タブ移動後にリロードしても同じタブで開き、ブラウザの戻る/進むでもタブ状態が追従します。スペック系は `部品分類`、`スペック詳細`、`スペック候補設定`、`共通スペック詳細`、`許容差スペック詳細`、`入力テンプレート` に責務を分け、入力テンプレートは一番右に置きます。

スペック系タブの左ペインは部品分類を選ぶための領域に限定し、分類名の横にそのタブで扱う登録数を小さく `登録:4個` のように表示します。選択後の右ペインのヘッダでは、`個別`、`入力候補`、`共通`、`許容差`、`テンプレート`、`行` など、そのタブの文脈に合う短い件数バッジで内訳を確認します。

### 部品分類

「抵抗」「コンデンサ」「FPGA」など部品の種類を表すタグです。部品には複数の部品分類を付けられます。部品分類はスペック詳細の候補と入力テンプレートの親でもあります。

- 一覧はドラッグ&ドロップで表示順を変更できます
- 使わなくなった部品分類は「アーカイブ」で候補から外せます（部品への紐付けは残ります）

### 部品分類と候補スペック詳細

`部品分類` は部品そのものに付ける種類・検索タグであり、スペック詳細の候補・並び順・既定値を束ねる入力候補グループでもあります。

例: 部品分類が `BJT` のとき、その中に `VCEO`、`コレクタ電流`、`hFE`、`fT` などの候補スペック詳細を並べます。

### 部品シリーズ

抵抗・コンデンサ・インダクタなど、同一シリーズの中に値違いが大量にある部品は、単体部品を1件ずつ並べるのではなく、`部品シリーズ` とシリーズ値一覧で扱います。一方で IC・MCU・センサ・モジュールなど、型番ごとの差分が大きい部品は従来通り単体部品として管理します。

部品分類には `シリーズを使わない`、`シリーズ登録も使う`、`シリーズ登録を推奨` の扱いを設定できます。

部品登録画面では `登録単位` で `単体` と `シリーズ` を切り替えます。通常の部品は `単体` のまま登録し、シリーズ値から登録部品を作る場合だけ `シリーズ` を選んで `部品シリーズ` と `シリーズ値` へ紐づけます。
登録画面の `シリーズ` は既存シリーズへの紐づけ専用で、その場では部品シリーズを新規作成しません。登録済みシリーズがない場合は `部品シリーズ未登録` と表示し、`マスタ・利用設定 > 部品シリーズ` へ移動して先にシリーズ値一覧を作成します。

値展開方式は E系列だけに固定しません。シリーズごとに次の方式を選べるようにします。

- `E系列`: E12 / E24 / E96 などの標準系列から値を生成する
- `基準系列 + 追加値`: E12 を基準にしつつ、一部だけ E24 の値を追加するような混在を正式に扱う
- `任意値リスト`: ツェナー電圧、水晶周波数、ヒューズ電流、コネクタ極数など、E系列に乗らない値を手入力・CSV貼り付けで持つ
- `範囲/刻み`: ピン数や定格電流のように、一定範囲を刻みで展開する

部品シリーズでは、部品分類を選ぶと `スペック詳細` の候補をその部品分類に絞ります。単位は選択したスペック詳細の標準単位を自動で使い、シリーズ側では直接編集しません。パッケージは `パッケージ分類` を選んでから `パッケージ詳細` を選びます。

E系列は `開始値` / `終了値` を実数で入力します。使える接頭語は選択したスペック詳細の `入力候補接頭辞` に従います。例: 容量スペックで `u/n/p/f` が候補なら `1fF`、`10pF` のように入力できます。0ΩはE系列の値ではないため、`0を含む` チェックで追加します。`範囲/刻み` はこれとは別方式で、開始値・終了値・刻み幅を同じ接頭語ルールで入力します。

シリーズ値一覧では、まだ部品として登録していない値と、登録済みの値を分けて表示します。`選択値を部品化` は保存済みで未部品化の値をチェックした時だけ実行できます。シリーズ全体の候補値は広く持ちつつ、実際に使う値だけを部品として登録して在庫・価格・保管棚を管理することで、E12中心に少量のE24が混ざる運用や、E系列外のツェナー・水晶でも破綻しにくくします。

既存部品を移行する場合は、同一メーカー・シリーズ名・部品分類・パッケージ・許容差で候補をグルーピングし、値違いの候補一覧を作ります。在庫や仕入先を持つ既存部品は削除せず、該当するシリーズ値へ紐づけます。自動判定できない部品は確認リストで手動リンクします。

設計解析ツールの結果は、案件・部品・BOMの行番号や識別名を付けて保存できます。設計解析画面では登録部品からスペック値を読み込んで解析入力へ反映し、保存済み解析との差分比較や、MCU ADC入力・3.3V電源・I2Cバス・TVS保護のテンプレート複製保存もできます。

### パッケージ分類・パッケージ詳細

パッケージは2階層で管理します。

- **パッケージ分類**（例: SMD、THT）— 大分類
- **パッケージ詳細**（例: 0402、0603、SOT-23）— パッケージ分類に属する個別形状

部品登録時はパッケージ分類を選んでからパッケージを選びます。
パッケージ詳細の外形寸法は `X / Y / Z` の3値で持ちます。`X` は縦または長手方向、`Y` は横または幅、`Z` は実装高さです。画面ではこの意味をラベルで明示します。

### スペック詳細

「静電容量」「耐圧」「周波数」など、検索・比較したい仕様項目を定義します。スペック詳細には **日本語名 / 英語名 / 記号 / 別名 / 標準単位** を設定できます。

- 日本語名は画面表示と標準検索名に使います
- 英語名・記号・別名は、英語データシートや略記号から同じスペック詳細へ照合するために使います
- 同じ日本語名のスペック詳細を複数登録できます。例: `電源電圧` を `VDD` と `VCC` で別々に持つ場合は、記号・別名で区別します
- `スペック詳細` タブでは先に部品分類を選び、その部品分類に持たせるスペック詳細を追加・編集・アーカイブします
- スペック詳細は `抵抗値` `耐圧` のように、選択中の部品分類でよく使う仕様項目です。ほかの部品分類でも使いたい項目は、`共通スペック詳細` か `許容差スペック詳細` から候補に入れます
- 共通スペック詳細は「共通スペック詳細」タブで左の部品分類を選び、登録済みの共通スペック詳細から、その部品分類の入力候補に入れるものを選びます
- スペック候補設定タブの行 `編集` は、候補側の範囲・扱い・既定の入力形式・既定単位・メモだけを編集します。名称・記号・別名・単位などスペック詳細そのものの編集は、各スペック詳細タブの `編集` で行います
- スペック候補設定タブで候補へ追加するときは、`スペック詳細から追加`、`共通スペック詳細から追加`、`許容差スペック詳細から追加` の3系統から既存項目を選びます。このタブではスペック詳細の新規作成やフリー入力を開きません
- スペック候補設定タブの候補追加・候補設定編集・候補順のドラッグ&ドロップは操作完了時に自動保存します。上下ボタンでの並び替えは使いません
- 許容差スペック詳細は、通常の共通スペック詳細とは兄弟の別棚として管理します。左の部品分類を選び、登録済みの許容差スペック詳細から、その部品分類の入力候補に入れるものを選びます。通常/許容差を切り替えるラジオや、許容差タブ内の行別 `許容差` バッジは置きません
- 許容差スペック詳細の例: `抵抗値許容差 ±5%`、`容量許容差 B級 ±0.1pF`、`容量許容差 Z級 +80/-20%`、`抵抗温度係数 ±100ppm/℃`、`容量温度特性 X7R`
- 記号は HTML ではなく `h_FE` `V_CBO` `V_CE-(sat)` のように保存します。`_` は下付き、`~` は上付き、`-` は通常表示へ戻す区切りです
- 標準単位は 1 つだけ設定します（例: 静電容量 → F、電流 → A）
- 接頭辞候補と表示接頭辞はスペック詳細ごとに設定できます。`B` / `bit` / `bps` 系は 10進接頭辞（`T/G/M/k/無印`）または IEC 接頭語（`Ti/Gi/Mi/Ki`）を選びます。一方を選ぶともう一方は自動で外れ、`m/u/n/p/f` は候補から外します
- スペック詳細を新規追加するとき、基準単位欄には `uF` や `kΩ` ではなく `F` や `Ω` を入力します。値欄で使える `u` / `k` などは `入力候補接頭辞` で選択します

### 入力テンプレート

入力テンプレートは、部品分類ごとにスペック行をまとめて追加する初期行セットです。候補スペック詳細の所属・並び順・既定値は `スペック候補設定` タブ、入力テンプレートは `入力テンプレート` タブで編集します。テンプレート行で選べるスペック詳細は、関連する部品分類の候補スペック詳細だけに絞ります。`共通` は部品分類として表示・選択せず、共通スペック詳細として管理します。

マスタ管理の追加・編集・候補選択系モーダルは内容量に合わせて幅を分けます。候補追加や入力テンプレート編集など一覧・行編集が必要なものは `modal-master`、パッケージ詳細とスペック詳細・共通スペック詳細・許容差スペック詳細・パッケージ分類・部品分類・候補設定編集は `modal-md`、確認ダイアログは短文専用の小幅モーダルとして扱います。

マスタ管理の並び順は、編集モーダルで数値を入力させません。パッケージ分類、パッケージ詳細、部品分類、候補スペック詳細の並び替えは、一覧上のドラッグ&ドロップで行います。`sort_order` は内部の保存値であり、ユーザーが直接調整する項目として表示しません。

マスタ本体を使わなくする操作は `アーカイブ`、候補関係の解除は `候補から外す` と表示します。`候補から外す` はスペック詳細そのものを削除する操作ではありません。候補から外す操作だけは確認ダイアログを挟みます。

部品登録時のスペック入力では、単位欄にスペック詳細の基準単位を使います。接頭語は値欄側へ付けます。例:

- `1u` + `A` は `0.000001 A`
- `1k` + `Ω` は `1000 Ω`
- `0.000000005 s` は `5ns`
- `1MB` は `1000000 B`、`1MiB` は `1048576 B`、`512KiB` は `524288 B` として扱います。`1Mbit` と `1Mbps` はどちらも10進の `M` として正規化します

登録画面ではスペック行に自由な「名前」欄はありません。必ずスペック詳細を選び、候補にない場合だけスペック追加カード下段の `スペックを新規で追加` からスペック詳細を登録します。値種別は `TYP`（代表値）、`MIN..MAX`（範囲）、`MAX`（最大のみ）、`MIN`（最小のみ）、`MIN/TYP/MAX` の5種を扱えます。検索用の数値は常に標準単位へ換算して行うため、`1uA` と `1e-6A` は同じ値として扱われます。

UI表示名は `部品分類` / `パッケージ詳細` / `スペック詳細` / `スペック候補設定` / `候補スペック詳細` / `入力テンプレート` / `共通スペック詳細` / `許容差スペック詳細` に整理しています。内部名の対応は API リファレンスと仕様書で管理します。

## 設計ツール

### 抵抗/容量ネットワーク探索

「全機能一覧 → 設計ツール → 受動部品ネットワーク/分圧設計」で、抵抗/容量ネットワーク、分圧、可変抵抗の計算を同じ画面で扱います。設計解析ツールでは `ネットワーク探索` / `分圧` / `可変抵抗` をメインタブとして扱い、別ページへ移動しなくても探索、分圧、VR分圧、可変抵抗候補を確認できます。

- 画面の上位タブは `ネットワーク探索` / `分圧` / `可変抵抗` です
- `ネットワーク探索` タブは抵抗/容量ネットワーク探索専用で、分圧UIは置きません。抵抗とコンデンサで直列・並列の合成式を切り替え、直並列混在候補も表示します
- 通常分圧とVR分圧は `分圧` メインタブ内で切り替えます。設計解析ツールハブ側の `NTC/PTC温度変換` は、温度-抵抗モデル、温度-電圧グラフ、感度の良い/悪い温度域、自己発熱、抵抗公差/サーミスタ公差の電圧破線、ADCコード表、線形化、固定抵抗候補へ責務を絞り、電気的な通常分圧/VR分圧候補は分圧タブのエンジンを使います
- `許容誤差`（`tolerance_pct`）は目標値へどれだけ近い候補を採用するかの探索許容範囲です。別入力の `部品許容差`（`element_tolerance_pct`）は、採用した各公称部品のばらつき確認用の条件です
- ネットワーク探索結果では、公称合成値に加えて、独立ばらつきのRSS目安範囲と、保証確認用の全素子同方向コーナー範囲を併記します。RSS目安は各素子の正規化感度を使い `sqrt(sum((S_i * 許容差)^2))` で求めます。コーナー範囲は直列・並列・直並列混在のR/C合成式が各素子値に対して単調であることを使い、全素子を下限値/上限値として同じトポロジを評価します
- `分圧` タブでは `VR調整なし` / `VR調整あり` を切り替えます。どちらも同じ分圧設計条件を使い、違いはVR素子を入れて出力範囲を調整するかどうかです
- 分圧条件は目標比率指定に加え、入力電圧 Vin と出力電圧 Vout から `Vout / Vin` の目標比率を直接計算できます。`VR調整あり` では同じ切替で出力下限/上限を電圧または比率範囲として指定できます
- `VR調整なし` と `VR調整あり` は同じ負荷条件を指定できます。抵抗負荷は出力からGNDへの抵抗で、`∞` は無負荷です。電流負荷は出力から引き抜く電流で、`0A` は無負荷です。電流負荷の計算には Vin が必要です
- 無負荷の指定は手入力前提にせず、抵抗負荷は `∞` ボタン、電流負荷は `0A` ボタンで設定できます。この操作は `VR調整なし` と `VR調整あり` の両方で使えます
- 分圧候補は R1/R2、実比率、負荷込み出力電圧、合計抵抗範囲、誤差、分圧列の回路電流、各抵抗の消費電力、抵抗合計電力をまとめて表示します
- 分圧は R1/R2 それぞれの許容差を設定でき、負荷込み出力の独立RSS目安範囲と全素子コーナー範囲を表示します。`VR調整あり` は R上/VR/R下 の許容差を個別に設定し、下限端/上限端の出力範囲を表示します
- E6/E12/E24/E48/E96、任意値、在庫部品を候補集合にできます
- 在庫限定では、電圧や許容差ではなく抵抗値/容量値のスペックを優先して使います。分圧タブ内では `VR調整なし` と `VR調整あり` の機能差をなくすため、現段階では在庫限定を共通条件から外しています
- ネットワーク探索の1〜2素子と分圧タブの候補はE系列全体を使い、3素子以上または直並列混在は探索量上限に達した場合に途中候補と次アクションを表示します
- 探索できない条件、候補プール数、打ち切り有無、非網羅探索条件、次アクションを結果に表示します
- 画面では候補の簡易回路表示、比較トレイ、在庫リンク、可変抵抗 + 固定抵抗の標準値候補選定を扱います
- 可変抵抗設計は `基準抵抗値` + `可変幅` で要求範囲を作ります。可変幅は `%` と `Ω` の両方を指定でき、`%` は基準抵抗値に対する幅として扱います
- 基準位置は `上限基準` / `中心基準` / `下限基準` から選びます。既存互換は `上限基準` で、例として `10kΩ, 20%` は `8kΩ〜10kΩ` になります
- 可変抵抗設計は算術上の理想値と採用候補を分け、`8kΩ` のような理想値だけを固定抵抗の採用結果として表示しません
- 現実装の採用候補は固定抵抗のE系列値、可変抵抗の標準VR値、カスタム値に限ります。在庫や購入リンクに紐づいていない候補は購入可能とは言いません
- 固定抵抗の標準値化で要求範囲を満たせない場合は、VRを範囲側に補正して固定抵抗を再計算します。直列はVR値を要求幅以上に上げ、並列は低端側を満たせるVRと固定抵抗を再計算します
- 可変抵抗 + 固定抵抗の候補には端点結果、目標下限/上限との差、固定抵抗/VRの補正有無、可変抵抗の標準値、CHECK/WARN判定を表示します。在庫/購入リンク未連携のためPASSは出さず、範囲包含する標準値候補はCHECK、範囲不足はWARNにします
- 可変抵抗 + 固定抵抗は、固定抵抗とVRそれぞれの許容差を設定でき、要求下限/上限端の独立RSS目安範囲とコーナー範囲を表示します
- `VR調整あり` は、Vin、出力下限/上限、指定した基準VR値から R上/R下 の固定抵抗候補を出します。基準VR値は緩い優先条件ではなく設計で使うVR素子の公称値として固定し、`10kΩ` 指定時に `200Ω` のような大きく異なるVR値は採用しません。負荷、候補値ソース、許容誤差、総抵抗範囲は `VR調整なし` と同じ入力を使います
- `VR調整あり` は端点で電流と電力が変わるため、最大回路電流、R上/VR/R下の最大消費電力、抵抗合計最大電力を表示します
- 現実装は公称値と無負荷/指定負荷モデルでの探索です。RSS目安は独立ばらつきの設計目安であり保証値ではありません。全素子同方向コーナーは保証境界確認用で、起きやすさを示すものではありません。温度係数、電圧係数、経年変化、寄生成分、同一ロット相関、実測分布、モンテカルロ統計、VRワイパ抵抗、電力、負荷の動的変動は別途確認してください。設計確認が残る候補は `PASS` にせず `CHECK` / `WARN` で表示します

### エンジニアリング計算

「全機能一覧 → 設計ツール → 計算」で各種電子回路計算補助ツールを使えます。

- SI 接頭辞（p/n/u/m/k/M/G/T）と PC 系接頭辞（Ki/Mi/Gi/Ti）を式中で使えます
- 複素数は `j` 表記で入力でき、直交形式と極座標（deg/rad）を確認できます
- 進数表示は 2進/8進/10進/16進、ビット幅、signed/unsigned を切り替えられます
- `solve(10=1/((1/x)+(1/20)), x)` のような方程式近似解、ユーザー定義関数、配列集計、色コード、日時差分を扱えます
- 関数一覧、補完候補、構文表示、履歴、固定式、結果コピーを備えます

### 設計解析ツールハブ

「全機能一覧 → 設計ツール → 設計解析ツール」で、ネットワーク探索、分圧、可変抵抗、EIA-96早見表、ADCスケーリング、電解コンデンサ寿命、NTC/PTC温度変換、電流検出、電源余裕、バッテリー稼働、比較器、熱設計、インタフェース、誤差/歩留まり、周波数応答、保護協調、ロジックIC参照、コネクタ設計/ピン配置、ケーブル判定、0Ω/未実装/ジャンパ整理、起動診断を同じ画面で確認できます。

- ツール入口は `すべて`、`受動部品`、`計測・変換`、`余裕・信頼性`、`保護・起動`、`参照・実装` の設計目的で絞り込めます。タブ自体の機能は維持し、目的を選んでから対象ツールへ入ります
- 各ツールは `仕様・前提確認` → `パラメータ入力` → `結果確認` → `次アクション` の順に確認できます。通常入力は各ツール内で行い、共通の詳細入力に残っていた最悪条件、定格、保存用条件の補足はツール別の `追加条件` へ統合します。同じ条件を共通欄と通常欄へ二重に出さず、1条件1入力欄で扱います
- 画面上の並びも、回路前提/確認記号、各ツールの入力・結果プレビュー、ツール別追加条件、最終判定と保存導線の順に固定します。個別ツール内の結果は即時計算のプレビュー、最終判定カードは verdict、支配要因、不足条件、次アクション、コピー、保存の出口として扱います。コネクタ設計では、入力フォームを先に置き、ピンマップとユーザー登録はその後の確認面に置きます
- 数値入力欄は `10k`、`100n`、`10m`、`1T`、`512KiB` のような工学接頭語付き入力を受け付けます。単位はラベル側をV/A/Ω/F/s/Wなどの基準単位へ寄せ、初期値・サンプル値は単位文字を付けずに数値と接頭語だけで表示します。ユーザー入力では `10kΩ`、`100nF`、`10mA` のような単位付き表記も受け付け、入力中にリアルタイム反映します。SI 接頭語は `Y/Z/E/P/T/G/M/k/無印/m/u/n/p/f`、IEC 接頭語は `Ti/Gi/Mi/Ki` を扱い、SPICE系表記の `meg` / `MEG` は `M` と同じ倍率として扱います
- ツールタブは初期状態では `受動部品` 目的の `ネットワーク探索` から始まります。前回開いたツールがある場合は、そのツールの目的に合わせて復元します。よく使う順へブラウザ内で並び替えでき、最後に開いたツール、目的フィルタ、タブ順は localStorage に保存されます。目的を切り替えたときに現在のツールが含まれなければ、その目的内の先頭ツールへ移動します。`初期状態へ戻す` で保存済みの順序、目的フィルタ、最後の選択を消せます
- 抵抗/容量ネットワーク探索、分圧、可変抵抗は設計解析ツール群の一部です。設計解析ツール内では `ネットワーク探索` / `分圧` / `可変抵抗` のメインタブとして扱い、分圧内だけ `VR調整なし` / `VR調整あり` を切り替えます
- `EIA-96早見表` はチップ抵抗器の3文字マーキングを対象に、2桁インデックス + 倍率文字から抵抗値へ変換します。`Z/Y/X/A/B/C/D/E/F` に加え、メーカー別表記で見る `R/S/H` も受け付け、倍率別96行表、抵抗値からの近傍コード、全倍率検索を表示します。0Ω、3桁/4桁SMDコード、マーキング省略品、メーカー独自表記は部品データシートで確認します
- `NTC/PTC温度変換` は温度-抵抗モデル、温度-電圧グラフ、感度の良い/悪い温度域、測定対象温度範囲の感度、サーミスタ電力損失、自己発熱、抵抗公差/サーミスタ公差による温度振れ、ADCコード、線形化、温度範囲ごとの誤差評価に集中します。通常分圧/VR分圧の候補選定は `分圧` タブで実行します
- `電流検出` はローサイド・シャント回路、ケルビン配線、電流検出アンプ、ADCの位置関係を図で示し、片方向のオフセットなし測定と双方向の0Aオフセット測定を切り替えます。入力電流から `Vshunt → Vout → ADCコード` をシミュレーションし、最小/最大電流時のアンプ出力電圧、ADC下限/上限余裕、ADCレンジ使用率、アンプ出力下限/上限余裕、ADC電流LSB、TCR、Rs電力定格余裕を同じ結果カードで確認します。ADCコードは範囲外をクリップし、表示コードはfloorで固定します。Rs定格超過は電圧レンジOKとは別に `FAIL理由` として明示します
- `電源余裕` は通常負荷合計と供給電力の余裕を直接表示し、効率は子レールから親レールへの上流換算にだけ使います。負荷ごとにレール名を指定でき、未指定時だけ電圧一致で割り当てます。レールツリー、dropout、最大負荷シナリオ、支配負荷を確認し、突入電流は時間幅と対象レールが未確定なら容量超過ではなくCHECK条件として扱います
- `バッテリー稼働` は入力を `電池パック`（種類、セル数、容量(Ah)、公称電圧、内部抵抗、使用可能容量）、`動作条件`（周期時間、システム最低電圧、要求稼働時間）、`周期負荷`（名称、負荷電圧(V)、負荷電流(A)、変換効率(%)、ON時間(s)）、`結果` の順に整理します。周期負荷は1セットを横並び、セットを縦並びで追加でき、LED・CPU・GPSのような同時ONを想定してON秒数合計が周期時間を超えても即FAILにはしません。負荷側電力をバッテリー側電力へ換算してWh/周期、平均電力、平均電流、全負荷同時ON前提のピーク負荷、容量ベース時間、電圧下限到達時間、実効稼働時間を算出します。主表示は実効稼働時間と制限要因に絞り、容量ベース時間と電圧下限到達時間は根拠値として並べます。電池種別とセル数に応じた満充電/公称/下限電圧を表示し、LiPo、ニッケル水素、アルカリ、マンガン、鉛の簡易放電曲線と内部抵抗、ピーク負荷から電圧降下グラフを描きます。グラフ右側には電池100%を使い切るまでの容量消費内訳円グラフを置き、各負荷のWh/周期比率が総消費の何%を占めるかを表示します。システム最低電圧が標準下限より低い場合は終端曲線を外挿して電圧下限到達時間へ反映し、深放電目安としてWARNします。グラフ右端は負荷時バッテリー電圧がシステム最低電圧へ到達する交点に固定し、その時点を残量0%として扱います。グラフの数値表示はSVG内tooltipへ一本化し、24hを超える場合は時間に加えて日、30日超は月、365日超は年スケールも併記します
- `比較器` はVin入力先を `+入力(非反転)` / `-入力(反転)` で切り替え、基準方式はVref方式/Vcc分圧方式を選べます。正帰還は常にV+へ戻し、+入力方式と-入力Vref方式は従来通りR1を使います。-入力+VCC分圧方式だけはR1をショート扱いにし、R2||R4のテブナン抵抗とR3でヒステリシスを計算します。Vin上昇時/下降時しきい値、出力遷移、ヒステリシス幅、基準Rth、しきい値公差、入力オフセット、入力バイアス、ノイズ余裕、抵抗候補を確認します
- `熱設計` は `P発熱源 → Rthチェーン → Ta周囲温度` の向きで熱抵抗段を可視化し、通常条件のTjが上限を超えた場合だけFAILにします。ワースト倍率やディレーティング不足はWARNとして残し、通常OKの設計を誤ってFAILにしません
- 有識者レビューでは、機能充足だけではなく、仕様・前提確認、パラメータ入力、結果確認、次アクション、画面上の仕様感も確認対象にします
- 結果は `PASS / WARN / FAIL / CHECK`、支配要因、不足条件、次アクション、コピー用サマリを返します。WARN/FAIL/CHECKのsummaryは「どれかが確認必要」のような曖昧な文ではなく、判定に使ったwarningや不足条件から、違反したパラメータ名と基準を先頭に出します
- 実装は設計ツール本体、機能別JSモジュール、Blade partialに分割しています。さらに部品登録/詳細、マスタ管理、エンジニア電卓、抵抗/容量探索、NetworkSearch、UiApiSurfaceSmoke、Tampermonkey補助も責務単位で分割し、一次コードは1000行目安を超えない構成にしています。公開関数、主要ヘルパー、副作用を持つ操作関数には目的、入力、出力、動作条件、副作用をコメントで残します
- 条件不足のTVS、ヒューズ、保護協調、推定熱抵抗を含む寿命計算などは `PASS` にせず、`CHECK` と不足条件を返します
- ロジックIC参照は 74LS/74F/74HC/74HCU/74HCT/74VHC/74VHCT/74LC/74LVC/4000/4500/5000 系の静的候補を返します。NAND/NOR/インバータ/シュミット/バッファ、FF/ラッチ、カウンタ、シフトレジスタ、デコーダ/エンコーダ、MUX/DEMUX、アナログスイッチ、加算器/比較器、モノステーブル、PLL/VCO など広い機能カタログを対象にし、シリーズ接続の電圧レベル判定は行いません
- `IF余裕` はUART/I2Cに加えて、送信側シリーズ+Vcc と受信側シリーズ+Vcc から VOH/VOL/VIH/VIL の近似値、受信側の入力耐圧/5V tolerant 条件、High/Low レベル余裕、入力過電圧リスクを判定します。静的近似なので、入力耐圧、出力電流、伝搬遅延、速度、温度範囲、5V tolerant 条件、ピン配置、負荷条件、未使用入力の固定方法は最終的に候補型番のデータシート条件で確認します
- コネクタ参照は `コネクタ設計/ピン配置` として実装済みです。USB 2.0/3.x/Type-C、D-sub、IDC、ピンヘッダ/ソケット、JST PH/XH/GH/SH、Molex KK/Micro-Fit、RJ45 などの標準テンプレートを備え、ユーザーは写真URL、図URL、データシートURL、mating face/solder side/cable side、ピン番号規則、定格、相手側部品を登録できます
- コネクタ設計/ピン配置では、カタログ検索、写真/図つきピンマップ、ピン別信号名、ピン割付、電圧、電流、並列電源ピン、シールド/FG、差動ペア、ケーブルAWG、derating、温度上昇、BOM/シルク注記を同じ画面で確認します。定格根拠、視点図、Pin1根拠、未割付ピンが不足する場合は `PASS` にしません
- 登録部品の `10kΩ`、`0.1uF`、`50mV` などの単位付きスペックは接頭辞を解釈して入力へ取り込みます
- 登録部品を指定すると、そのスペック値を解析入力へ取り込めます
- 結果カードには部品候補・在庫候補・部品詳細へのリンクが付きます
- 解析条件は案件・部品・BOM行と一緒に保存できます。案件は案件名/事業名/案件番号検索、部品は型番/通称/メーカー検索で選択し、ID直接入力は使いません
- 保存済み解析は一覧から title/verdict/summary/案件/部品/BOM/更新日を確認でき、差分表示、入力へ復元、削除確認まで同じ保存パネルで操作できます
- MCU ADC入力、3.3V電源、I2Cバス、TVS保護の解析テンプレートを入力へ反映またはユーザー/案件単位で複製保存できます

## 困ったときは

| 困りごと | 参照先 |
|---|---|
| 部品が見つからない | [「部品を探す」](#部品を探す)の詳細フィルタでメーカー・パッケージ・スペック範囲を試す |

| スペックの単位が出ない | [「スペック詳細」](#スペック詳細)で基準単位を登録する |

| 画面の表示が崩れる | ブラウザをハードリロード（Ctrl+Shift+R）する |
| DB を以前の状態に戻したい | [「バックアップから書き戻す」](#バックアップから書き戻す管理者のみ)を参照 |
| 権限を上げてほしい | [「ロールを変更する」](#ロールを変更する管理者のみ)を管理者に依頼 |

## 環境構築

> サーバーの構築・保守を担当する方向けの情報です。

### 動作環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 22.04 |
| Web サーバー | Apache2 + PHP-FPM |
| PHP | 8.3 |
| Laravel | 12 |
| Vue | 3 |
| Tailwind CSS | 3 |
| PostgreSQL | 16 |

### 初期構築手順

```bash
git clone <repo> /web/BitsKeep
cd /web/BitsKeep/bits-keep

composer install --no-dev
npm ci && npm run build

cp .env.example .env
php artisan key:generate
# .env の DB_* / APP_URL / FILESYSTEM_DISK を設定

# ⚠ 実行前に接続先・件数・バックアップ・復元手段の4点を確認すること
php artisan migrate --force

php artisan storage:link
```

### コード変更後の反映

```bash
cd bits-keep
npm run build   # 必ずビルドしてからブラウザをリロード
```

### やってはいけない操作

| 操作 | 理由 |
|---|---|
| `composer run dev` の実行 | `public/hot` が生成されブラウザが Vite サーバーに接続しようとして CSS/JS が全滅 |
| `php artisan serve` の実行 | Apache と競合する |
| `.env` を SQLite に変えて `migrate --force` | 本番 DB が空になる（2026-04-12 事故の再現） |

### DB 変更前の必須チェック（4点）

1. 接続先確認（`.env` の `DB_HOST` / `DB_DATABASE` を目視）
2. 件数確認（`SELECT COUNT(*) FROM components` などで実データを確認）
3. バックアップ確認（ダウンロード済みのダンプがあるか）
4. 復元手段確認（`psql` で書き戻せる状態か）

### バックアップ（CLI）

```bash
# DB 取得
PGPASSWORD=postgres pg_dump -h 127.0.0.1 -p 5432 -U postgres bitskeep \
  | gzip > /tmp/bitskeep_$(date +%Y%m%d).sql.gz

# DB 書き戻し
zcat /tmp/bitskeep_YYYYMMDD.sql.gz \
  | PGPASSWORD=postgres psql -h 127.0.0.1 -p 5432 -U postgres bitskeep

# ファイル（画像・データシート）取得
tar -czf /tmp/bitskeep_files_$(date +%Y%m%d).tar.gz \
  /web/BitsKeep/bits-keep/storage/app/public/

# ファイル復元
tar -xzf /tmp/bitskeep_files_YYYYMMDD.tar.gz -C /
```
